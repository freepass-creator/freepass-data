# 노출 쓰기 도구 권한 규칙 (2026-10-16)

> 대표 몫 한 장 «A③ 노출 쓰기 도구 권한 규칙» 중 AI 가 정할 수 있는 부분(1번 커맨드 센터 배정, 유지보수 작성).
> 도구: `scripts/exposure-apply.mjs`(노출 하향·재노출 적용). 정본 코드·시험이 이 문서보다 우선한다.

## 1. 원칙

- **원천 기준**(대표 상시 승인 2026-10-12 «무조건 원천 기준, ERP 는 바뀌어야 될 데이터»): 원천이 판매 불가/없음이면 노출을 내리고, 다시 판매 가능이면 다시 올린다.
- **삭제 없음**: 문서는 그대로 두고 `listable`·판매 상태 칸만 바꾼다. 원문·가격 행·정책은 불변. 이전 값은 `publication_withdrawal_prior` 에 보존(복원 가능).
- **계약 잠금·고정 문서는 건드리지 않는다**(`locked_by_contract`·`status=계약중`·`_pin_state=pinned`).
- **정시 원천 엔진(source-cycle)이 기본 경로**다. 이 도구는 엔진이 못 하는 일회성 정리(승인 공급사 일괄 하향 등)와 사고 복구에만 쓴다.

## 2. 누가·언제·무엇을 (권한 표)

| 작업 | 실행 주체 | 사전 승인 | 입력 | 상한 |
|---|---|---|---|---|
| 원천 계획에 따른 하향·재노출 (`--plan`+`--supplier`) | 유지보수 AI (어느 세션이든 «받음» 후) | 상시 승인(원천 기준) | exposure-plan/v1 계획 파일(digest 포함, 15분 이내). 생성 도구 `sellable-count` 는 현재 main 에 없음(닫힌 PR #495·#499 가지) — 재도입 PR 필요 | 한 공급사 현재 판매 중의 **50% 미만**(`--max-ratio`) |

## 3. 안전선 (도구가 강제하는 것 — 어기면 쓰기 전 중단)

① 계획 digest 재계산 일치 ② 계획이 `--max-age-min`(기본 15분) 이내 ③ 계약 잠금·고정·이미 보류 표식 문서 건너뜀 ④ 비율 상한 ⑤ 쓰기 직전 문서 재읽기(공급사·판매 상태·`updateTime`)
⑥ 쓰기 전 비공개 백업 파일 기록·되읽기 확인 ⑦ 쓴 뒤 되읽기로 표식·가격 행 불변 대조. 차량번호는 끝 4자리만 출력, 키·번호 전체 출력 금지.

## 4. 운영 규칙

1. **시험 실행 먼저**(기본이 쓰기 0). `--apply` 는 시험 실행 결과(대수·건너뜀 사유)를 보고 한 뒤에만.
2. **정시 회차(:00)·이안카 감시(:50) ±10분 구간에는 실행하지 않는다**(같은 문서를 엔진이 쓸 수 있음; 엔진은 `updateTime` 조건부 쓰기라 충돌은 실패로 끝나지만 불필요한 재시도를 만든다).
3. **보고 형식**: «받음 → 완료 + 근거»: 공급사 코드·하향/재노출 대수·건너뜀 사유별 대수·백업 파일 이름·되읽기 결과·계획 digest 앞 16자.
4. **복원**: 백업의 `publication_withdrawal_prior` 로 되돌린다(별도 복원 계획 → digest 승인). 복원도 계약 잠금은 건드리지 않는다.
5. **새 쓰기 경로·옵션 추가는 Codex 읽기 관문(P1 만 차단) 뒤 병합**하고, 이 문서의 표를 같은 PR 에서 갱신한다.

## 5. 대표 결정이 필요한 것(AI 가 임의로 정하지 않음)

- 계약 잠금 상태 차량의 노출 처리, 하드 삭제.
- «출고불가 공급사» 지정(승인 근거 문구의 주체).
- 하향 비율 상한(50%) 변경.
