# 공급사 상품가격 조건 입력 규격

## 목적

공급사가 지금 당장 모든 가격변경 조건을 제공하지 않더라도 FreePass Data 구조는 모든 조건축을 받을 수 있어야 한다.

공급사에게는 가격을 다시 만들어 달라고 하는 대신 다음 세 가지를 채우게 한다.

1. 기본값 — 현재 등록된 기준 대여료가 어떤 조건인가
2. 선택 가능값 — 고객이 무엇으로 바꿀 수 있는가
3. 가격변경 규칙 — 기본값에서 선택값을 바꾸면 얼마가 변하는가

## 기준 상품 입력 예시

- 기간: 36개월
- 기준 주행거리: 연 20,000km
- 기본 운전자 연령: 만 26세 이상
- 운전자 범위: 본인+직계가족
- 추가운전자: 0명
- 대물: 1억원
- 대인: 무한
- 자차 자기부담률: 20%
- 자차 최소/최대 면책금: 50만원 / 100만원
- 정비: 미제공
- 월대여료: 650,000원
- 보증금: 2,500,000원

## 변경 가능 조건

| 조건축 | 기본값 | 선택 가능값 | 가격변경 |
| --- | --- | --- | --- |
| 주행거리 | 20,000km | 30,000 / 40,000 | 1만km당 +10만원 또는 +10% |
| 운전자 연령 | 만26세 이상 | 만23세 / 만21세 | 23세 +5만원, 21세 +10만원 |
| 추가운전자 | 0명 | 1명 | 1인당 +5만원 |
| 대물 한도 | 1억원 | 2억원 / 3억원 | 공급사 입력 |
| 자차 최소면책금 | 50만원 | 30만원 / 70만원 | 공급사 입력 |
| 정비 | 미제공 | 연1회오일 / 연2회오일 / 제공 | 공급사 입력 |
| 긴급출동 | 연5회 | 무제한 | 공급사 입력 |
| 대차 | 불가 | 동급대차 | 공급사 입력 |

현재 공급사가 가격을 안 주는 칸은 비워둘 수 있다.
단, 가격 변화 없음과 아직 안 받음은 구분한다.

- 0원 / 0% = 가격 변화 없음이 확인됨
- 빈칸 = 아직 가격을 받지 않음
- 불가 = 선택 자체가 불가
- 협의 = 자동 산출 불가, 수동 확인 필요

## 가격변경 규칙 형식

한 규칙은 다음 구조를 가진다.

- 어떤 조건이 바뀌었을 때
- 추가 조건이 있다면 무엇인지
- 어느 결과를 바꾸는지
- 어떻게 바꾸는지

지원 연산:
- ADD_FIXED: 정액 가산
- ADD_RATE: 기준 대여료 또는 현재 대여료의 비율 가산
- ADD_PER_UNIT: 1만km, 1명 등 단위당 가산
- MULTIPLY: 월대여료 또는 보증금의 배수
- SET_FIXED: 특정 조건에서 금액 고정
- REQUIRE_EXPLICIT_VARIANT: 공급사가 별도 가격표를 줘야만 산출

## 반드시 열어둘 조건축

현재 데이터에서 이미 존재하거나 상품가격에 영향을 줄 수 있는 축:

- 기간
- 약정 주행거리
- 운전자 연령
- 운전자 범위
- 추가운전자 수
- 면허경력
- 보험 포함 여부
- 대인 한도
- 대물 한도
- 자기신체사고 한도
- 무보험차상해
- 자차 보상기준
- 자차 자기부담률
- 자차 최소/최대 면책금
- 정비 서비스
- 긴급출동
- 대차 서비스
- 대여료 카드결제
- 보증금 카드결제
- 탁송
- 반납형/인수형

향후 새로운 조건이 생겨도 ConditionDimension으로 추가할 수 있고 가격 규칙 엔진 자체는 바꾸지 않는다.

## 중요한 원칙

- 기준 대여료에는 반드시 적용조건 스냅샷이 붙는다.
- 명시 가격 variant가 있으면 계산 규칙보다 우선한다.
- 하나의 변경이 월대여료와 보증금 둘 다 바꿀 수 있다.
- 여러 조건이 동시에 바뀔 수 있다.
- 규칙은 우선순위와 적용조건을 가진다.
- 모르는 규칙은 추정하지 않는다.
- 최종 결과에는 어떤 기준가격과 어떤 규칙들이 적용됐는지 trace를 남긴다.
