# 원천 한 장 — 원문 → 대수 → 정제 (2026-10-14)

대표 2026-10-14: «원문을 먼저 가지고 오고 대수를 맞추고 이 가지고 온 것들을 정제를 하면 되잖아. 옵션, 정책 이런 것들 다 그 회사에서 주는 곳을 보면 거기에 정책이 있다. 값이 숫자로 존재하거나 산출식으로 존재한다.»

## 원칙 (모든 원천 공통)
1. **원문**: 공급사가 주는 곳(API·시트·ERP·홈피) 그대로 전부 가져온다. 가공 전 원문은 원문층에 남긴다.
2. **대수**: 원문 대수 = 등록 대수가 맞는지 먼저 본다(판매가능·계약중·출고불가 칸별). 일부만 읽혔으면 쓰지 않는다.
3. **정제**: 값은 공급사가 준 **숫자** 아니면 공급사가 정한 **산출식**에서 나온다. 우리가 지어내지 않는다.
   - 원문 0·빈칸은 «무보증»이 아니다(자리표시). 무보증은 공급사가 무보증이라고 적었을 때만.
   - 산출식으로 계산한 값은 «계산값(규칙 코드)» 표시를 단다. 대여료가 바뀌면 다시 계산되고, 안 맞으면 미상.
   - 숫자도 산출식도 없으면 «미상»이고, 그건 결함으로 보고 정책 출처를 찾는다(대표 확인 대상 아님).
