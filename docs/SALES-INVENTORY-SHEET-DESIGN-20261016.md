# 영업자용 재고 구글시트 — 설계 한 장 (2026-10-16, 박대표 10-15 하허호무심사 방 약속 «구글시트로 내려놓겠습니다»)

상태: DESIGNED. 코드·시트 쓰기 없음. 라이브 시트 생성·공유 설정은 별도 승인·대표 손 목록.

## 1. 재사용 가능한 투영이 있는가
| 후보 | 상태 | 판정 |
| --- | --- | --- |
| **F01**(활성 상품 시트, 대표 2026-10-08 «상품 시트는 F01 하나») — 탭 4개(상품리스트·손오공상품·픽업구독·오플구독), freepasserp4 `erp5-ssot-refresh` 가 중앙 snapshot 에서 발행 | 운영 중 | **내용은 재사용, 문서는 별도** — F01 문서를 영업자에게 공유하면 관리·숨김 탭·내부 열까지 노출될 수 있다. 같은 중앙 snapshot·같은 표시 규칙으로 «영업자용 보기» 문서를 따로 발행하는 것이 안전하다 |
| F86(원본·이력 보존용, 비활성) | 보존 | 쓰지 않는다(수수료 열 포함) |
| 공급사 전용 재고 시트 | 공급사 입력용 | 쓰지 않는다(공급사 내부·입력 구조) |
| ERP5 공개 피드(`/v1/public/catalog/feed`) | 운영 중 | **입력 원천으로 재사용** — 허용 목록(public-allowlist)이 이미 수수료·내부 메모를 제외한다. 시트 칸은 이 허용 목록의 부분집합으로만 구성 |

결론: 새 «영업자용 재고» 문서를 만들되, 데이터는 공개 피드와 같은 허용 목록·같은 중앙 snapshot 에서 만든다(F01 발행과 같은 시점의 snapshot ID 를 문서에 표시).

## 2. 칸
포함(공개 피드 허용 목록 안): 차량번호·차종 정제 4칸(제조사·모델·세부모델·세부트림, 정제 전은 «차량 정보 확인 중»)·연식·주행거리·연료·색상·대여료(기간별)·보증금(기간별, 확인 필요 표시)·출고 상태(출고가능·계약중)·상품 구분·사진 링크·옵션(기본/유상 — 옵션 설계 승인 뒤).
제외(명시): 수수료·원가·정산, `partner_memo`·`sales_notes`·공급사 정책 메모, 잠금·내부 상태, 공급사 코드(결정 필요 — 아래), 원문 차명(정제 전 원문은 노출하지 않음).
- 차량번호: 공개 피드가 이미 `car_number` 를 내보내므로 영업자 범위로 문제 없음(공개 범위 확인 완료). 고객·계약 정보와 결합하지 않는다.
- 공급사명: **영업자용은 표시**(공개 피드 `provider_name` 그대로 — ERP·개발 확인 2026-10-16: 일반·하허호·이안카 영업 채널은 공급사명을 보인다). 소비자용 문서(audience=consumer)가 따로 생기면 그 문서만 숨긴다. 차이는 발행 옵션 `audience` 하나.

## 3. 갱신
- 주기: 정시 회차(:00) 직후 한 번(시간당 1회). 엔진 회차 종료 후 snapshot 이 새로 확정됐을 때만 발행(변경 없으면 건너뜀).
- 전체 교체: 새 «버전 탭»(예: `재고_YYYYMMDD_HHmm`)을 만들어 검증(행 수·필수 칸·금지 값 검사) 통과 시 «현재» 탭으로 교체하고 직전 버전 탭은 최근 N개 보관(숨김) — 되돌림은 직전 버전 탭 복원. 실패하면 이전 «현재» 탭이 그대로 남는다(부분 갱신 없음).
- 시각: 문서 맨 위에 snapshot ID·갱신 시각·건수. 출고가능/계약중 외 상태(출고불가)는 목록에서 제외.

## 4. 공유
- 보기 전용, 영업자 그룹(구글 그룹)에만. 링크 공개·«링크가 있는 모든 사용자» 금지. 편집 권한은 서비스 계정·관리자만.
- 공유 설정은 AI 가 바꾸지 않는다 — **대표 손 목록**으로 전달: ① 문서 소유 계정 ② 영업자 그룹 구성원 ③ 보기 전용 확인 ④ 다운로드·복사 허용 여부(제한 권장).
- 영업자 측 사본·캡처는 통제 불가 — 공급사 승인 범위 안의 값만 내보낸다는 점을 대표가 확인.

## 5. 채널 확대
같은 발행기가 «채널 허용 목록»(칸 집합·상품 범위·공급사 노출)을 받는 구조로 두면 하허호무심사 외 영업 채널(팀·그룹별)은 허용 목록과 공유 대상만 추가하면 된다. 채널별로 보이는 공급사·상품 구분을 다르게 할 수 있다. 채널 추가는 대표 승인 항목.

## 6. 단계
1. 대표 결정: 공급사명 노출·칸 목록·갱신 주기 확정.
2. DATA: 발행기 설계 → 허용 목록 투영 + 검증 + 버전 탭 교체(읽기 전용 plan 으로 칸·건수 확인). **CODED(plan 만)**: `src/application/sales-inventory-sheet.ts`, CLI `src/jobs/plan-sales-inventory-sheet.ts`(`--feed`·`--compare-feed`·`--audience`; 쓰기 0, 위반 있으면 종료 코드 2).
3. B3Q/ERP: 문서 생성·공유(대표 손 목록)·첫 발행 검증(새 조회로 칸·행 수·금지 값 0 확인).

## 7. 보완 (커맨드 센터 2026-10-16, 박대표 10:02 «거기는 ERP에 있는 전체 차량 동일하게 돌려놓겠습니다»)
1. **범위 = ERP5 에 노출 중인 전체 차량(계약중 표시 포함).** 시트 행은 «공개 피드 출력 그대로»로 만든다 — `buildPublicProductFeed`(노출 판정 `listable !== false`·공급사·채널 필터 포함)의 결과를 행의 유일한 입력으로 쓰고, 시트용 별도 필터·재계산을 두지 않는다. 그러면 시트 목록은 ERP5 와 같은 중앙 snapshot·같은 허용 목록에서 나온 것이라 목록이 어긋날 수 없다(건수·차량 키는 발행 때 피드와 대조).
2. **칸 = ERP5 «전체 정보» 공개 칸 기준.** 공개 피드 `PublicProduct` 의 필드(차량번호·차종·연식·제원·기간별 대여료/보증금·상태·상품 구분·사진·정책 공개 칸)만. 수수료·원가·내부 메모(partner_memo·sales_notes)·잠금·원문 제외는 피드 허용 목록이 이미 보장한다(발행 검증: 금지 필드·금액/수수료 꼴 문구 0).
3. **공급사명(정정 2026-10-16)**: 영업자용 시트는 공개 피드 `provider_name` 을 «표시»한다(ERP·개발 확인: 영업 채널은 supplier 표시, 소비자용 audience 만 숨김). 소비자용 문서가 생기면 `audience=consumer` 로 공급사 칸을 뺀다. 이전 «확인 전 기본 숨김» 안은 폐기.
4. **갱신/버전**: 정시 회차 직후 시간당 1회, 버전 탭 검증 통과 후 «현재» 교체·직전 N개 보관(되돌림 가능).
5. **첫 발행 순서**: 계획(읽기 전용: 칸·건수·피드 대조)·검증(번호·칸 허용 목록 위반 0) → 박대표 확인 → 발행. 공유 설정(영업자 그룹 보기 전용·링크 공개 금지)은 대표 손 목록.
6. **링크 전달 절차**: 시트 링크를 영업방에 올리는 것은 박대표 직접(또는 박대표 확인 후 EN1 이 전달). AI 는 링크를 임의로 게시하지 않는다.
