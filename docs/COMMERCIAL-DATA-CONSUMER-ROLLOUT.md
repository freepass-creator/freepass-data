## 상품·정책 의미와 데이터 품질 감사 규칙

이 문서는 데이터 필드의 업무 의미와 감사 방법을 정의한다. 공급사별 승인 정책이나 고객 계약을 대체하지 않는다. 공급사 원문 위치·세부 대조표·실제 상품 식별자는 접근이 제한된 감사 증거에 보존한다. 공개 저장소에는 업무 사전, 집계 진단과 검증 범위만 남긴다.

### 상품·정책을 읽는 기준

- 상품은 공급사·상품종류·인수/반납형·기간·연간 약정거리·월대여료·동일 조건 보증금·정책참조의 묶음으로 해석한다. 최저 대여료에 다른 조건의 보증금이나 주행거리를 붙이지 않는다.
- 값에는 단위, 기준액, 주기, 적용 대상, 조건, 예외, 효력일, 원천 위치와 버전이 필요하다. 숫자 10만으로 원/만원/퍼센트를 정하지 않는다.
- 보증금·선납금·계약금·월대여료·만기인수금·수수료는 서로 다른 사실이다. 0, 무료, 없음, 불가, 협의, 미입력, 해석 실패를 구분한다.
- 2026-10-07 대표 결정: 보증금은 해당 조건의 0과 무보증 근거가 확인될 때만 ZERO/0으로 제공한다. 공란·누락·미해석·placeholder·금지/충돌은 UNKNOWN, 표시 문구는 **보증금 확인 필요**다. 조건별 state와 금액을 함께 소비하며 UNKNOWN에는 확정 금액이 없다. 원천 갱신에서 이전 KNOWN/ZERO가 UNKNOWN으로 바뀌면 `DEPOSIT_EVIDENCE_LOST_REQUIRES_REVIEW`로 전체 갱신을 보류하고 이전 revision/RAW를 보존한다. 이 보존을 새 원천의 현재 확정으로 해석하지 않는다. 기존 ACTIVE와 새 보류 원천의 현재성 표시 연결은 별도 소비처 검증이 필요하다.
- 2026-09-30 사용자 결정: **프리패스 수수료 = 지급수수료(`channelPayoutFee`)**, FreePass → 영업채널이다. 공급사 연동 수수료는 공급사 → FreePass의 `supplierBillingFee`이며 내부 마진과 구분한다. 상대별 제공 기준과 미구현 운영 연결은 [수수료 연동 기준](READ-RUNTIME.md#수수료-연동-기준--사용자-결정-2026-09-30)을 따른다.
- 명시된 나이별 가산은 해당 나이의 일반 가산을 대체하는지 기존 입력 규격으로 확인한다. 자격 불가와 비용 존재가 충돌하면 요금 우선순위만으로 계약 자격을 허용하지 않는다.
- 연간 약정거리 상향의 월 가산과 실제 초과거리의 1km당 정산은 별개다. 비율에는 기준액과 적용 순서, 기간에는 기산점·일할·반올림 근거가 필요하다.
- 카드결제 가능은 수수료 0을 뜻하지 않는다. 서류 요구 체크는 제출·검증 완료가 아니며, 빈칸은 기존 값 삭제 명령이 아니다.
- 내부 자유 메모를 공개하는 방식으로 조건 누락을 해결하지 않는다. 필요한 계약 사실을 출처·적용범위가 있는 공개 가능 필드로 분리한다.

### 추가 감사에서 확인한 전달·갱신 경계

2026-09-30 추가 관측은 원천 일부 지정 행, ERP 동일 transaction 캡처, 별도 시점 공개 API 및 기존 workflow 실행 증거에 한정된다. 상세 원천 대사는 비공개 증거로 보존하며 전 공급사·전 소비처·실제 계약 검증 완료로 확대하지 않는다.

- 정책을 정확히 연결한 공개 상품의 일부에서 DB에 존재하는 나이별 조건이 빠지고 일반 조건만 전달되는 현상을 확인했다. 실제 견적·계약 계산 영향과는 구분하며, 승인된 연령별 필드 전달 계약이 필요하다.
- 기본 운전자 연령이 문자열이면 현재 numeric-only reader가 읽지 못한다. 숫자로 해석된 사실, 해석하지 못한 원문, 빈값을 별도 진단한다. 기본값으로 덮어 일치시키지 않는다.
- 공개 응답에서 보충된 기본값은 원천에 명시된 값과 출처를 구분해야 한다. 값의 존재만으로 원천 의미 보존을 증명하지 않는다.
- 감사 workflow 성공은 capture·증거 readback·포인터 갱신의 성공이다. 공급사 원문 정책의 최신화나 내용 충돌 해소를 뜻하지 않는다.
- 매시간 schedule 설정과 실제 실행 간격, watchdog의 허용 간격은 서로 다른 사실이다. 실행 이력과 현재 기준을 함께 확인한다.
- 기존 ERP 공통 수집 엔진의 변동 모드는 이미 존재하는 차량만 갱신하는 분기가 있다. 신규 차량 수집과 다른 전용 엔진은 별도로 검증한다.
- DB 내부 정책 참조 정합화는 운영정책 Sheet 본문을 다시 읽는 동기화가 아니다. 참조 무결성과 정책 내용 최신성을 따로 검증한다.
- 판매시트 발행 단계 성공 뒤에도 실제 셀·화면 readback과 각 소비처의 동일 release 사용 여부를 확인해야 한다.
- Sheet importer가 빈칸이나 모든 서류 체크 해제를 패치에서 제외하면 ERP의 이전 값이 남을 수 있다. 명시적 해제 의도와 지원되는 command를 확인한다.

### Count-only 정책 진단

`inspectErp5Capture().policyFactCoverage`는 아래 정보를 집계하며 원문값·문서ID·고객정보를 출력하지 않는다.

- 원본 문서 수, 반환 사실 수, 건너뛴 문서 수와 안전한 decode 오류 코드.
- 건너뛴 문서의 top-level timestamp 공존 수. 중첩 필드의 전수 검사나 실패 원인 판정이 아니다.
- 정책코드 대신 문서ID를 사용한 사실 수, 중복 코드 수와 같은 코드의 초과 사실 수. 실제 매퍼는 공급사도 확인하므로 초과 사실이 항상 가려진다고 단정하지 않는다.
- 현재 reader가 이미 반환하는 명시적 비활성 표시 수. 지원 표시는 `_deleted=true`, `is_active=false`, `status=deleted|retired`이며 모든 폐기 상태를 검증한 것이 아니다.
- 연간 주행거리의 숫자 해석/미해석/누락, 누락 내 필드 부재/null/빈 문자열 구분.
- 기본 운전자 연령의 숫자 해석/미해석/누락 구분.

숫자 해석은 기존 reader가 정수를 반환한다는 뜻이며 업무상 유효값 승인과 다르다. 진단은 decoder 허용 타입, 정책 효력, 반환 사실, canonical 쓰기, 소비처 전환을 변경하지 않는다. 원문 단위와 정책 효력을 해결하기 전 HOLD를 유지한다. dry-run artifact 계약·digest에는 집계를 추가하지 않는다.

검증은 합성 회귀검사와 동일 캡처의 진단 추가 전후 결과 대사를 사용한다. 원본 정책 효력·단위 해석·공개 API 수정은 별도 작업이며 이 진단 변경의 통과로 해제하지 않는다.

## 역할 경계

FreePass Data는 소비처의 화면을 결정하지 않는다.
FreePass Data의 책임은 렌터카 상품 데이터를 의미별로 정리하고, 근거와 불확실성을 포함해 소비하기 쉬운 계약으로 제공하는 것이다.

Admin, ERP.com, Kakao Ops, Sheet, Estimate 등 각 소비처는 같은 데이터 카탈로그에서 자기 목적에 필요한 항목을 선택한다.

## 데이터 분류

### 1. basisRows — 원천 가격 사실
- 기간별 원천 월대여료
- 보증금
- 그 가격이 성립하는 조건
- 조건별 provenance
- UNKNOWN / policy match

### 2. dataCatalog.dimensions — 조건축 전체
조건마다 다음 메타데이터를 제공한다.
- key / label
- group: TERM / MILEAGE / DRIVER / INSURANCE / MAINTENANCE / PAYMENT / DELIVERY / SETTLEMENT / OTHER
- role: PRICE_INPUT / ELIGIBILITY / CONTRACT_ONLY
- valueType
- defaultValue / allowedValues / options
- sourcePolicyKeys
- mayAffect: MONTHLY_RENT / DEPOSIT / UPFRONT_FEE / ELIGIBILITY

### 3. dataCatalog.classification — 골라 쓰기 위한 색인
- priceInputKeys: 가격을 만들거나 바꿀 수 있는 조건
- eligibilityKeys: 계약 가능 여부를 판단하는 조건
- contractOnlyKeys: 가격 계산과 별개인 계약조건
- groups: 업무영역별 조건키 목록

### 4. dataCatalog.pricingModifiers — 현재 확인된 가격 가감 정보
- 주행거리 상향
- 연령 하향
- 추가운전자
- 향후 보험/정비/대차 등의 typed adjustment rule로 확장

### 5. policyFacts / contractFacts
- policyFacts: 상품값 선택/산출에 관여하는 정책 사실
- contractFacts: 계약상 권리·의무·처리 조건
- 한 사실이 가격 입력이면서 계약서 표시값일 수도 있으므로 의미를 잃지 않고 분류한다.

### 6. derived — 파생값
소비처가 반복 계산하지 않아도 되도록 유용한 파생값을 제공한다.
- lowestBasisPrice: 원천 Basis 중 최저 월대여료와 그 조건
- defaultConditionResult: 명시적 기본조건을 적용한 산출 결과

파생값은 표시 지시가 아니다.
소비처는 lowestBasisPrice를 쓸 수도 있고 defaultConditionResult를 쓸 수도 있고 둘 다 안 쓸 수도 있다.

### 7. quality — 데이터 품질
- unresolvedDimensionKeys
- partialBasisTermKeys
- ambiguousPolicyTermKeys
- unclassifiedPolicyFactKeys

소비처는 품질 상태를 보고 표시/업무/검수 정책을 자체 결정한다.

## 핵심 원칙

FreePass Data는 다음 질문에 답한다.
- 우리가 아는 사실은 무엇인가?
- 어떤 조건의 가격인가?
- 그 사실은 어디에서 왔는가?
- 어떤 조건이 가격을 바꿀 수 있는가?
- 어떤 조건은 계약 가능성만 바꾸는가?
- 어떤 계약조건이 존재하는가?
- 무엇을 아직 모르는가?
- 어떤 파생값을 안전하게 계산할 수 있는가?

FreePass Data는 다음 질문에는 답하지 않는다.
- Admin 목록에 무엇을 보여줄 것인가?
- ERP.com 상세의 첫 줄은 무엇인가?
- 고객 화면에서 어떤 배지를 쓸 것인가?
- Kakao 답변에서 몇 개 항목을 말할 것인가?

그 결정은 각 소비처의 책임이다.

## 호환 필드

현재 소비처 전환 중이므로 commercial block의 listing/preview/conditionSummary는 당분간 호환용으로 유지한다.
정본 의미는 dataCatalog와 basisRows에 두고, 이후 소비처가 안정적으로 dataCatalog를 사용하면 호환 필드 제거 여부를 별도로 결정한다.
