# 원천 상태값 → 프리패스 상태 매핑표 (초안, 2026-10-14)

대표 지시: 원천에서 없어진 것은 삭제·철회 표식이 아니라 «출고불가·계약중·상품화중» 상태로 바꾸고, 신규는 상태를 배정해 편입한다. 변경 없는 차는 건드리지 않는다.

## 프리패스 상태 어휘 (코드 정본: `src/domain/erp5-inventory-status.ts`)

| 프리패스 상태 | status_kind | 노출(listable) |
|---|---|---|
| 즉시출고, 출고가능 | 가용 | 예 |
| 출고협의 | 협의 | 예 |
| 상품화중 | 준비 | 예 |
| 계약중 | 선점 | 예(계약중 문서는 엔진이 잠금 취급: 원천이 바꾸지 않음) |
| 출고불가 | 불가 | 아니오 |

원천에서 사라진 노출 문서는 `SOURCE_ABSENT` 사유로 `출고불가`·listable=false 로 내려가며 삭제하지 않는다.

## 결정 반영 (커맨드 센터 2026-10-14)

- 오토플러스: «목록 있음 = 출고가능, 1400/없음 = 출고불가(노출 제외)» 가정 승인. 홈피는 게시=판매 가능 이분법이고 계약 차는 홈피에서 빠진다. **사라짐 = 계약중 가능성이 있으나 원천으로 구분 불가**이므로 출고불가로 둔다.
- 손오공: #572 아티팩트의 상태 필드 분포가 나오면 값 그대로 매핑한다(출고가능/계약중/출고불가/상품화중 의미가 분명한 값만). 의미가 불분명한 값은 «확인 필요»로 노출 제외·보류 목록에 올리고 알려진 값부터 진행한다.
- F05·아이카·이안카·아이언: 위 현행 코드 기준 확정.

## 결정 필요 (쓰기 경로를 열기 전)

1. 손오공: 상태 필드 이름·값 목록은 #572 대조표 아티팩트(상태 분포)로 확정한다. 그 전에는 «출고가능 → 출고가능, 계약중 → 계약중, 그 밖 → 보류»만 가정한다.
2. 오토플러스: 홈피에는 상태 필드가 없다. 대표 결정(홈피 = 판매 가능 정본)에 따라 «홈피 목록에 있음 → 출고가능, 상세 조회 1400/없음 → 출고불가» 로 둔다. 계약중·상품화중은 홈피로 알 수 없어 ERP4 시트 값이 있을 때만 유지한다.
3. 원천에서 사라진 차의 `계약중` 보존: 현행 엔진은 계약중 잠금 문서를 원천 부재로 내리지 않는다(잠금 우선).
4. 보류 규칙(유지): 가격 없음, 번호 불명, 중복 충돌, 마스터 미매칭은 목록만 남기고 쓰지 않는다.
