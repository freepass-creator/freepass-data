# F01 · F86 · ERP 동일 회차 발행

사용자 2026-09-21 추가 요구: 같은 시간에 두 Google Sheets와 ERP에 반영한다. 동일한 주기로 각자 최신 데이터를 조회하는 것으로 충족했다고 보고하지 않는다.

## 완료 조건

- 한 회차가 확정한 입력 버전 하나에서 F01, F86, ERP 상품 표시를 만든다. 세 결과에 같은 snapshot/release ID와 회차 기준 시각을 연결한다.
- F01 표준, F86 레트로, ERP 화면은 각자의 표시 규격을 유지한다. 공급사별 재분류·금액 추정·누락 값 임의 보완을 하지 않는다.
- 세 사용처 모두 실제 반영 결과를 다시 읽고 각 사용처의 의도된 노출 범위에 따라 차량 키·분류·기간별 가격/보증금·필수 표시값을 대조한다. 공급사별 중복 뷰나 내부/공개 필터 차이를 무조건 같은 대수로 강제하지 않는다.
- 최종 완료는 F01, F86, ERP 세 검증이 같은 release에 대해 모두 성공했을 때다. 한 곳이라도 실패하거나 ERP 화면이 이전/다른 버전을 읽으면 부분 발행 또는 HOLD로 기록한다.
- 독립된 Google Sheets 두 문서와 웹 캐시에 하나의 원자적 커밋은 없다. 요청을 병렬로 보낸 것만으로 같은 순간에 전환됐다고 주장하지 않는다. 반영 시작/완료 시각과 사용처별 실제 버전을 기록한다. 엄격한 동시 공개가 필요하면 사전 준비/전환 방식과 허용 전환 구간을 별도로 설계·검증한다.
- ERP 상품 표시 버전을 고정하더라도 실시간 계약락/판매가능 여부를 과거 값으로 돌리지 않는다. 이 경계를 훼손하는 스냅샷 적용은 금지한다.

## 현재 확인된 차이

2026-09-21 조회한 freepasserp4 workflow는 원자 갱신 → snapshot → 공개 카탈로그 대사 → F01 → F86 → 시트 대조 순서다. `verify-whitelabel-publication.mts`는 snapshot과 현재 Firestore products/policy를 대조하여 receipt를 쓰며, ERP 웹 자체를 해당 snapshot으로 전환하지 않는다.

main 앱의 `lib/server/whitelabel-erp5-catalog.ts`는 현재 products/policy를 직접 읽으며 60초 캐시를 사용한다. 내부 ERP와 공개 화면도 이 경로를 소비한다. 따라서 현 구현은 세 화면의 동일 회차 공개를 보장하지 않는다. 배포된 웹의 현재 코드/캐시/응답 버전은 별도 실측이 필요하다.

시트 표시 규격의 PR461/운영 pin 후보 PR462 및 24탭 readback PASS는 이 추가 요구의 완료 증거가 아니다. 기존 필수 검토 예외 승인 질문도 이 더 넓은 ERP 변경의 승인으로 확대하지 않는다. 운영 pin은 미전환 상태로 유지하고 ERP 소비 경로와 세 사용처의 완료 증거를 보완한다.
