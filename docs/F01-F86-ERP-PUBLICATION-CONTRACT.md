# 중앙 정본과 소비처별 사용 계약

사용자 2026-09-21 정정: 중앙 정본 한 곳을 Google Sheets 두 개, ERP.com과 그 외 화이트라벨들, Admin이 가져다 쓰는 구조다. 소비처를 고정된 세 곳으로 세거나 Admin·추가 화이트라벨을 제외하지 않는다.

중앙 Firebase 프로젝트는 사용자 직접 지정한 `freepasserp5`다. 실제 저장소/읽기 서버의 연결 및 아직 전환하지 못한 항목은 [ERP5 소비처 런타임](ERP5-CONSUMER-RUNTIME.md)에 기록한다.

```text
원천/API → FreePass Data 중앙 정본
                      ├─ Google Sheets F01 (표준 표시)
                      ├─ Google Sheets F86 (레트로 표시)
                      ├─ ERP.com + 각 화이트라벨 (웹 표시)
                      └─ Admin (운영 업무 화면)
```

GitHub는 코드·계약의 정본이며 운영 데이터 자체의 저장소는 아니다. 위 그림은 확정한 목표 책임 구조로, 모든 운영 연결이 이미 이관됐다는 뜻이 아니다. Sheets는 중앙 정본의 출력물이고 웹/Admin은 중앙 정본이 제공하는 API 또는 검증된 소비처별 데이터를 사용한다. 직접 API 조회와 시트 출력 갱신은 같은 정본·버전 계약을 지키는 서로 다른 전달 방식이다.

## 완료 조건

- 중앙에서 검증한 정본 버전 하나를 F01, F86, ERP.com, 각 화이트라벨, Admin이 소비한다. 각각의 응답/출력에 사용한 snapshot/release ID를 추적한다. 시트 갱신 시각과 웹 조회 시각을 억지로 같은 값으로 만들지 않는다.
- F01 표준, F86 레트로, ERP/화이트라벨, Admin은 각자의 권한·업무·표시 규격을 유지한다. 소비처에서 독자적인 공급사 재분류·금액 추정·누락 값 임의 보완을 하지 않는다. Admin의 운영 입력도 중앙 데이터의 승인된 쓰기 경로를 거쳐 반영한다.
- 실제 연결 대상 목록을 관리하고 각 화이트라벨도 개별 소비처로 확인한다. 모든 대상의 실제 응답/출력을 다시 읽고 의도된 노출 범위에 따라 차량 키·분류·기간별 가격/보증금·필수 표시값을 대조한다. 공급사별 중복 뷰나 Admin 내부/공개 화면의 필터·권한 차이를 무조건 같은 대수로 강제하지 않는다.
- 최종 완료는 해당 발행의 대상 소비처가 모두 중앙의 같은 버전을 사용함이 검증됐을 때다. 누락된 Admin/화이트라벨, 실패한 시트, 이전/다른 버전을 읽는 웹을 제외하고 전체 완료라고 말하지 않는다. 부분 반영 또는 HOLD를 대상별로 기록한다.
- 독립된 Google Sheets 두 문서와 웹 캐시에 하나의 원자적 커밋은 없다. 요청을 병렬로 보낸 것만으로 같은 순간에 전환됐다고 주장하지 않는다. 반영 시작/완료 시각과 사용처별 실제 버전을 기록한다. 엄격한 동시 공개가 필요하면 사전 준비/전환 방식과 허용 전환 구간을 별도로 설계·검증한다.
- ERP 상품 표시 버전을 고정하더라도 실시간 계약락/판매가능 여부를 과거 값으로 돌리지 않는다. 이 경계를 훼손하는 스냅샷 적용은 금지한다.

## 현재 확인된 차이

2026-09-21 조회한 freepasserp4 workflow는 원자 갱신 → snapshot → 공개 카탈로그 대사 → F01 → F86 → 시트 대조 순서다. `verify-whitelabel-publication.mts`는 snapshot과 현재 Firestore products/policy를 대조하여 receipt를 쓰며, ERP 웹 자체를 해당 snapshot으로 전환하지 않는다.

main 앱의 `lib/server/whitelabel-erp5-catalog.ts`는 현재 products/policy를 직접 읽으며 60초 캐시를 사용한다. 내부 ERP와 공개 화면도 이 경로를 소비한다. 이 코드 확인만으로 모든 소비처가 중앙의 같은 버전을 사용한다고 보증할 수 없다. 배포된 ERP.com·각 화이트라벨·Admin의 실제 연결, 캐시, 응답 버전은 각각 실측해야 한다.

시트 표시 규격의 PR461/운영 pin 후보 PR462 및 24탭 readback PASS는 전체 소비처 연결의 완료 증거가 아니다. 기존 필수 검토 예외 승인 질문도 더 넓은 ERP·화이트라벨·Admin 변경의 승인으로 확대하지 않는다. 운영 pin은 미전환 상태로 유지하고 각 소비 경로와 실제 사용 버전의 증거를 보완한다.
