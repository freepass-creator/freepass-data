# 이안카 사진 → 우리 구글 드라이브 저장 설계 (한 장, 코드 없음) — 2026-10-14, DATA

> 대표 결정 10-14: 이안카 사진은 **ONE 원천에서 내려받아 우리 구글 드라이브에 저장**한다(우리 서버 GCS 저장은 계속 안 함). 파일럿 10대 승인 포함. 이 문서는 설계와 대표 손 항목만이며 코드 PR 은 설계 확인 뒤다. 앞선 조사 한 장(`IANCAR-PHOTO-OPTIONS-20261014.md`)의 b안을 구체화한다.
> 키·사진 URL 은 어디에도 쓰지 않는다. 아래 «필드 키 이름»과 «경로 형태»만 적는다.

## 1. 원천 사진 주소 확보 (필드 키만)
- 차량 식별·번호·상태는 기존 ONE 목록 수집(source_raw)에서 가져온다(추가 호출 없음).
- 차량 상세 `GET /v1/vehicles/{vehicle_id}` 한 번 → `photos[]`: 키 `photo_id`·`url`·`representative`(코드 `iancarOnePhotoIds` 가 이미 검사: 신원 일치·`stale:false`·URL 이 `/v1/vehicles/{id}/photos/{photo_id}` 와 정확히 일치·쿼리 없음·대표 ≤1·최대 200).
- 사진 본문 `GET /v1/vehicles/{vehicle_id}/photos/{photo_id}` (Bearer). 참조 24시간 유효 → **상세 조회와 다운로드를 같은 잡·같은 차량 단위로 연달아** 하고 참조를 저장하지 않는다(만료 대응).

## 2. 다운로드 잡 (일 1회, 직렬, 상한, 건너뜀, 압축, 재시도 0)
| 항목 | 규칙 |
|---|---|
| 주기 | 일 1회 새벽(KST 04:00대 한 번). 정시 전체 회차에 묶지 않는다(커맨드 센터 결정). 이안카 상류 정지(UPSTREAM_STALE) 중에는 실행 안 함 |
| 대상 | 노출 중(listable) 이안카 차량. 파일럿 = 10대(번호 오름차순 상위 10), 확인 뒤 전체 |
| 직렬·간격 | 동시 1. 요청 사이 1.5초 이상(손오공 상세 1.5초 선례). 이안카 서버 부하 방어 |
| 상한 | 차량당 최대 10장(대표 1 + 앞 9, 파일 이름 순서 = 대표 먼저). 1회 잡: 차량 40대·사진 400장·실행 40분 중 먼저 닿는 것에서 중단, 남은 건 다음 날 |
| 건너뜀 | 차량 지문 = digest(순서 있는 photo_id 목록 + 대표 id). 드라이브 번호 폴더의 지문과 같으면 그 차량은 상세 조회만 하고 다운로드 0 |
| 압축 | 기존 `renderVehiclePhotoRendition('detail')`: 래스터만(jpeg·png·webp), 입력 ≤8MB·≤24MP, 긴 변 960px·JPEG q80(EXIF 회전 반영). 압축본만 저장하고 원본 바이트는 남기지 않는다. 방법 코드 `IANCAR_COMPRESSED_COPY` |
| 실패 | **재시도 0**. 사진 1장 실패 → 그 차량은 이번 회차 폴더·등록 변경 없음(부분 앨범 금지), 다음 날 다시. 429(Retry-After 존중하되 대기하지 않음)·5xx 연속 3회·타임아웃 → 잡 즉시 종료(남은 차량 다음 날) |
| 규모 | 93대 × ≤10장 ≈ 930장, 압축 후 장당 약 100~200KB → 약 100~190MB. 최초 전체 ≈ 40분 × 며칠(상한 400장/일), 이후는 지문 바뀐 차만 |

## 3. 드라이브 구조·이름 규칙
```
<이안카 폴더>/
  차량사진/                  ← «링크가 있는 모든 사용자 보기»(대표 결정, 이 폴더만)
    <차량번호>/              ← 번호 폴더(기존 승인 사진 규칙과 같음)
      01.jpg  02.jpg …       ← 대표가 01, 이후 상세 목록 순서. 2자리 번호, 확장자 .jpg(압축본이 항상 JPEG)
  서류/                      ← 비공개(공유 안 함)
```
- 파일 이름에 photo_id·URL 을 넣지 않는다. 폴더 `appProperties`: `iancarPhotoSet`(차량 지문 앞 16자)·`copiedAt`(UTC). 파일 `appProperties`: `srcIdx`(원천 목록 순번).
- **대표 확인 1건**: 번호 폴더 이름에 차량번호가 들어가므로 «차량사진» 폴더 링크가 공개되면 링크를 가진 사람은 하위 번호 목록을 볼 수 있다. 기술적으로 사진 서빙은 서버(서비스 계정 보기 공유)가 하므로 **공개 링크는 필수가 아니다**. 공개를 유지할지(번호 목록 노출 허용) 한 번 확인 필요.

## 4. 등록 (photo_original_refs, 빈 칸만·CAS·전후 기록)
1. 업로드·크기/체크섬(Drive `sha256Checksum`) 확인 후 `plan-photo-links`(폴더×문서 스냅샷)로 계획 → 등록 도구 `--method IANCAR_COMPRESSED_COPY`.
2. **빈 칸만**: 문서에 `photo_original_refs` 가 비어 있을 때만 쓴다. 이미 있으면 보류(`ALREADY_HAS_PHOTOS`). 예외 «교체»는 기존 refs 가 전부 `IANCAR_COMPRESSED_COPY` 이고 폴더 지문이 달라졌을 때만(다른 방법·사람 승인 사진은 절대 덮지 않음).
3. **CAS**: 문서 `updateTime` 조건부 쓰기, 한 건씩 되읽기(등록 도구의 현행 동작), 쓰기 전 문서 백업(비공개)과 audit 한 줄(번호 끝 4자리·장수·전후 지문).
4. 파일럿에서 확인할 것: refs 등록 뒤 ERP5 목록 imageUrl 이 생기고 `PHOTO_PENDING` 표식이 화면에서 풀리는지(우선순위: 승인 refs > 이안카 원천 서빙, 코드로 확인됨 — 실제 화면은 파일럿에서 확인).

## 5. 갱신·삭제 없음
- 일 1회. 지문이 같은 차는 변경 0. 앨범이 바뀐 차만 폴더 파일을 같은 이름(01.jpg…)으로 덮어쓰고 refs 교체(§4-2).
- **삭제 없음**: 원천에서 사라진 차의 폴더·파일·refs 를 지우지 않는다. 노출은 문서 `publication_withdrawal` 이 내리므로 사본은 보관만 되고 서빙되지 않는다. 정리(삭제)는 사람 승인 별도.

## 6. 필요한 권한 — 대표 손 항목 (값 입력 없음, 한 단계씩)
권한 설정은 AI 가 바꾸지 않는다. 아래는 대표가 그대로 실행하는 순서다.
1. 구글 드라이브에서 «이안카 폴더» 안에 **«차량사진»** 폴더와 **«서류»** 폴더가 있는지 확인(없으면 만들기). 서류 폴더는 공유하지 않는다.
2. «차량사진» 폴더 → 공유 → **업로드 주체 서비스 계정 이메일**(B3Q 가 알려 주는 «…@….iam.gserviceaccount.com» 한 개)을 **편집자**로 추가. (이 한 폴더만. 다른 폴더·내 드라이브 전체는 공유하지 않는다.)
3. (대표 결정대로 공개 유지 시) «차량사진» 폴더 → 공유 → 일반 액세스 «링크가 있는 모든 사용자» → **뷰어**. 서류는 건드리지 않는다. (§3 확인 사항 참고)
4. 서비스 계정이 이 폴더에 쓰려면 GCP 프로젝트에서 **Google Drive API 사용 설정**이 켜져 있어야 한다(콘솔 «API 및 서비스»에서 한 번 «사용»). 이미 읽기 도구가 드라이브를 읽고 있으면 켜져 있는 것이다.
5. 서비스 계정 토큰을 개발 PC 에서 쓰려면(키 파일을 만들지 않고) **대표/관리자 계정이 그 서비스 계정에 «서비스 계정 토큰 생성자» 역할을 갖는지** B3Q 가 확인한다 — 없으면 B3Q 가 필요한 한 줄을 대표에게 따로 요청한다(키 파일 생성은 하지 않는다).
- 요청 범위 요약: «서비스 계정 1개가 차량사진 폴더 1곳에 편집자» 가 전부. 서비스 계정이 다른 드라이브 자원에 접근하지 못하므로 API 범위(`drive`)가 넓어도 실제 접근은 그 폴더로 한정된다.

## 7. 안전
- API 키는 프로세스 메모리에만, 로그·알림·보고·시험 출력에 키·사진 URL·경로·응답 본문 금지. 로그는 건수·번호 끝 4자리·상태 코드·분류 코드만.
- 원천 응답 헤더·오류 본문을 중계하지 않는다. 래스터 형식·크기·픽셀 상한 검증(압축 모듈 기존 검사), SVG 거부.
- 드라이브 쓰기 실패·429·지문 불일치는 모두 «변경 0» 으로 끝나며 문서 refs 는 업로드 완료·체크섬 확인 뒤에만 바뀐다. 롤백 = refs 되돌림(백업) + 폴더는 보관.
- 공급사 호출은 하루 한 번·직렬·간격·상한으로 제한한다(이안카 서버 부하·429 방지).
