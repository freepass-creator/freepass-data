## 0. 불변 규칙(인수 시 그대로)
- 마스터·차종 기준 한 장은 **대표만** 바꾼다. AI 는 마스터에 없는 이름을 만들지 않는다(후보 큐 → 대표 승인).
- 새 무인 쓰기 경로는 **기본 꺼짐** + 대표 승인 뒤 켠다(엔진이 autoApprove 라 코드 게이트가 설계 기본).
- 번호는 끝 4자리만, 키·ID 비공개. 쓰기는 B3Q 안전 경로(승인 digest·백업·lastUpdateTime·되읽기)만.
- 독립 검토(Codex) → B3Q 관문 → 병합 → 엔진 교체 → 적용. 판단·적용 증거는 되읽기 건수로 남긴다.
- 신선도 점검 2시간 주기(세션 크론): B3Q 에 «heartbeats.jsonl 마지막 줄 + schtasks FreePass-Source-Cycle» 회신 요청, 2회 연속 무응답·UNHEALTHY 면 센터에 원천·원인·마지막 정상 시각. **인수 세션에서 이 크론을 다시 걸 것**(세션 종속).

## 3. AI 정제 판단 규칙(재사용)
1. 마스터에 있는 제조사·모델·세부모델 이름·ID 만 선택(새 이름 금지, 괄호·세대 표기 이름에 섞지 않음).
2. 원문 차명 + 연식(최초등록·연식) + 연료·배기량으로, 마스터 세부모델 **생산 기간에 그 연식이 드는 항목이 정확히 하나**일 때 선택. 겹치거나 밖이면 세부모델 비움(모델만).
3. 연식이 두 기간에 걸쳐도 «원문의 한정어(더 뉴·디 엣지·어반·베리 뉴)가 선택한 세부모델 이름에 그대로 있고 겹치는 다른 세부모델 이름에는 없을 때만» 선택.
4. 하이브리드·EV 는 별도 세부모델(원문·연료 변형 일치), 원문 개발코드는 이름·기간과 모순되지 않을 때만 근거.
5. 트림은 원문·연료로 하나로 특정될 때만, 철자 차이(비지니스↔비즈니스)는 비움 + 별칭 후보 큐.
6. 사람 입력·확정·잠금·철회 문서는 비접촉. 근거는 evidence 에 «마스터 항목 ID·연식∈기간» 한 줄.
7. 마스터 기간이 이상해 보이면 고치지 않고 대표용 한 장에 올린다(외부 지식 추정으로 실제 시기를 단정하지 않음).

## 4. 환경·도구
- 계획·적용: `apply-vehicle-name-reference-repair`(VEHICLE_NAME_REPAIR_PLAN, 승인 digest 환경 변수, `--apply`). 항목 종류: productIdentityRepairs(전체/level MODEL)·productTrimRepairs.
- 읽기 전용 도구: `build-master-addition-candidates --listable-only`, 입력 스크립트(같은 폴더).
- 교훈: 다른 머신의 파일 경로는 읽을 수 없다 — 자료는 메시지 본문으로. 추정으로 원인을 단정하지 말고 실제 거절 문구를 먼저 받는다(#716 오판).
