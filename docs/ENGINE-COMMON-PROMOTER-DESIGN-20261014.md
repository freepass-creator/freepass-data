# 엔진 공통 승격기 설계 — ERP4 쓰기를 끊고 «원천 어댑터 추가만»으로 (2026-10-14, 설계만)

방향(커맨드 센터 2026-10-14): ERP4 를 끊은 뒤 «source_raw → 상품 레이어» 승격을 엔진이 공통으로 한다. 원천이 늘면 어댑터만 추가한다.
상태: DESIGNED. 아래 «이미 엔진에 있음» 표시는 코드 확인(현재 main), «공백»은 ERP4 가 하던 일 중 엔진이 아직 안 하는 것.

## 1. 구조 (이미 엔진이 하는 공통부)

```
원천 어댑터(원천별) ─→ SourceProductRecord(공통 레코드) ─→ planSourceCycle(공통) ─→ applySourceCycle(공통: CAS·백업·되읽기) ─→ products 문서
   F05 시트 / 아이카 시트 / 이안카 ONE / 오토플러스 시트·홈피 / 손오공 API / (아이언 홈피)
```

공통 레코드 계약: 식별자(번호 우선, 번호 없으면 시트 UID·행 지문 FP-키), 상태(saleAvailable + raw 표시 상태), 기간별 월 대여료·보증금(KNOWN/ZERO/UNKNOWN), 원문(raw), 상품 구분(raw.product_type·product_group). 어댑터는 이 레코드만 만들고 쓰기·상한·가드는 공통부가 한다.

## 2. ERP4 가 하던 일 vs 엔진 현황

| ERP4 담당 | 엔진 현황 | 공백·할 일 |
|---|---|---|
| 신규 편입 | 있음: 1차 무조건 편입(비노출), 회차 상한 max(100, 노출 50%), 한 회차 한정 상향 | — |
| 변동값(가격·상태) 갱신 | 있음: UPDATE/REEXPOSE/DOWNGRADE, 보증금 보존, 드리프트 보류(-AcceptDrift) | — |
| 판매 완료·부재 하향 | 있음: 완전 읽기에서만, 비율 가드, 계약 잠금 보호 | — |
| 계약 잠금(정산 장부) | 있음: locked 문서는 원천 값이 덮지 않음, «잠금 우선» 보고 | 잠금 해제 승인 절차(사람) |
| 차종 마스터 매칭(_pin_state new-high → 제조사·모델·세부모델·세부트림) | **공백**: 엔진은 마스터 미매칭 신규를 `vehicle_review_required`·원문 차명으로 편입만 한다 | 아래 §3 «정체성 승격» |
| 보증금 규칙(국산 월대여료×2·수입×3, «계산값» 표시) | **공백**: 오토플러스 홈피·손오공 등 보증금 없는 원천의 보증금은 UNKNOWN | 마스터의 국산/수입 판정 필요 → §3 같은 모듈 |
| 상품 구분(product_type) | 부분: 월렌트·손오공 탭별 기록 | 원천 어댑터마다 raw.product_type 규약을 명세로 고정 |
| 사진 연결 | 별도 도구(#586 사진 연결 도구 2종)·이안카 사진 보관 | 승격기에서 «사진 주소 → 상품 사진 칸» 단계 추가는 사진 정책 확정 후 |
| 발행(시트·소비처 게시) | 엔진 밖(발행 단계) | 변경 없음 |

## 3. 공통 승격기에 더할 것(순서)

1. **정체성 승격(차종 마스터 매칭)** — 정식 정정 경로가 이미 있는 영역이라 «엔진이 직접 쓰기» 대신 계획서(plan JSON)를 만든다:
   엔진 회차가 비노출·정보 부족 문서의 원문 차명을 마스터 별칭과 대조해 «하나로 특정되는 경우만» 정체성(제조사·모델·세부모델·세부트림) 후보를 계획서로 낸다 → 기존 `repair:vehicle-name-parity`(계획 → 검토 → 백업 → 적용 → 되읽기)로 적용. 규칙은 기준 한 장(§4-5 «지어내지 않는다», 별칭은 조건 없이 하나로 이어질 때만). 엔진이 마스터를 직접 고치지 않는다.
2. **노출 승격 게이트** — 비노출(INFO_INCOMPLETE) 문서가 «가격 있음 + 정체성 확정 + 상태 확정» 이면 다음 회차에 REEXPOSE(이미 가격·상태는 있음; 정체성 조건만 추가 여부는 소비처 요구에 따라 결정).
3. **보증금 계산값** — 마스터의 국산/수입 판정이 확정된 차에 한해 규칙값을 «계산값» 표식과 함께 채운다(원천이 준 값이 있으면 원천이 이긴다).
4. **원천 어댑터 규약 명세** — 새 원천은 §1 레코드 계약 + 상태 어휘 매핑표(SOURCE-STATUS-MAPPING) + 완전성 판정(닫는 태그·직전 대비 급감·상세 성공)을 충족하는 어댑터 하나만 추가한다. 규약 시험(어댑터 공통 시험 틀)을 둔다.

## 4. ERP4 쓰기 끊는 순서(원천별, 이중 쓰기 금지)

| 원천 | 엔진 쓰기 | ERP4 쓰기 정지 |
|---|---|---|
| F05·아이카·이안카 | 이미 엔진(ERP4 는 읽기 전용 소비) | 해당 없음 |
| 오토플러스(RP023) | 시트 우선 어댑터 운영 중 | ERP4 RP023 쓰기 제외 PR(db3dd9ae) 합침 |
| 손오공(RP012) | API 어댑터 구현·합침(스위치·키 대기) | ERP4 RP012 승인 등록·변동 쓰기 정지 → 스위치 |
| 아이언(RP006) | 어댑터 있음(홈피 스키마 불일치 — RSC products 기준 재작성 필요) | ERP4 approveAll(cedf726d) 경로 유지 → 엔진 어댑터 재작성 뒤 전환 |

원천 하나씩 «엔진 dry-run 병행 → ERP4 정지 → 엔진 켜기 → 5칸 지표 확인» 순서. 롤백은 스위치 0 + ERP4 정지 되돌림.

## 5. 아침 보고에 모을 «대표 확인» 후보

- 마스터 미매칭 신규의 정체성 승격을 «계획서 자동 생성 + 사람 검토 1회»로 갈지, 확정 규칙에 한해 자동 적용까지 갈지.
- 보증금 계산값(국산×2·수입×3)을 원천 값이 없을 때 노출 조건으로 인정할지.
- 아이언 엔진 어댑터를 RSC 기준으로 새로 쓸지(ERP4 approveAll 경로를 계속 쓸지).
