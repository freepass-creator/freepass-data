# 이안카 사진 복원 설계 한 장 (2026-10-16)

> 1번 커맨드 센터 배정 «A⑤ 이안카 사진 복원 설계(썸네일 ≤25KB 별도 잡)». 설계만 — 구현·켜기는 대표 승인·공급사 허용 확인 뒤.
> 전제 문서: `IANCAR-PHOTO-COPY-FIRST-SERVING.md`(사본 우선 서빙), `IANCAR-PHOTO-GATE-ROLLOUT.md`, `SOURCE-CYCLE-OPS-HANDOFF-20261014.md` §2(사진은 `photo_cache.urls` 만 이미지로 읽힘).

## 1. 목표와 현황

- 목표: 이안카 노출 차량(약 100대)에 **대표 사진 1장**을 안정적으로 보이게 한다. 화면 요청이 이안카(ONE) 서버를 두드리지 않는다(대표 2026-10-14·15 «압축해 우리 드라이브로 가져와 연동»).
- 현황: 사진은 현행 **전량 차단 유지(대표 방침)**. 라이브 /api/catalog(10-16 기준) 노출 105대 중 imageUrl 있음 55, 없음 50(사본 refs 등록분과 일치하는지는 구현 전 대조). 이안카 ONE 은 목록에 imageUrl 이 없고 상세 앨범 리졸버가 필요(`photoPending`).
- 이미 있는 것: 사본 우선 서빙 코드(refs `IANCAR_COMPRESSED_COPY` 면 드라이브 사본, 없으면 404/라이브), 등록 도구 `scripts/ops/register-approved-photos.mjs`, 사진 렌디션 캐시(#562).

## 2. 설계 — «별도 잡» 한 개

```
이안카 사진 복원 잡 (별도 스케줄, 정시 회차와 분리, 기본 꺼짐)
  입력: 노출 중 RP031 상품 중 «사본 refs 없음» 차량 (회차당 상한 N대, 기본 10)
  1) 차량 단위로 ONE 상세 앨범에서 대표 사진 1장만 읽는다 (차량당 1회, 간격 ≥3초, 429/503 즉시 중단)
  2) 리사이즈: 긴 변 640px, JPEG 품질을 낮춰 ≤25KB(썸네일). 원본 저장 없음.
  3) 우리 드라이브 폴더 freepasspics/이안카/<번호 또는 ONE ID> 에 1장 저장
  4) register-approved-photos --method IANCAR_COMPRESSED_COPY 로 refs 등록(백업·되읽기)
  5) 화면: photo_approved_count>0 인 차만 imageUrl (사본 우선 서빙 그대로)
  출력: 회차 보고(처리 대수·실패 사유 코드별·건너뜀), 차량번호 끝 4자리만
```

## 3. 안전·정책

| 항목 | 규칙 |
|---|---|
| 원천 부하 | 회차 상한 10대·차량당 1회·≥3초 간격·429/503 즉시 중단·오류 3회 연속이면 잡 정지(다음 회차 재개) |
| 저장 | 썸네일만(≤25KB), 원본 비저장, 사본에 서명·만료 URL 없음 |
| 번호 없는 차(`iancar_…`) | ONE 차량 ID 로 폴더명 구성, 번호 확인 동선 답이 오면 이름만 정정(이동 기록) |
| 켜기 순서 | ① 공급사 허용 확인(리사이즈·재저장·한도) 답 수신 ② 대표 승인 ③ 시험 3대 → 되읽기 200 확인 ④ 회차 상한으로 점증 |
| 되돌리기 | 잡 꺼짐 + `IANCAR_LIVE_PHOTO_FALLBACK=off`(라이브 호출 0), 등록 refs 는 철회(삭제 없음, prior 보존) |
| 개인정보 | 번호판 가림은 별도 정책 결정 대상(대표) — 이 잡은 원천 사진을 그대로 축소만 한다 |

## 4. 열린 결정(대표)

1. 공급사(이안카) 사진 재저장·리사이즈 허용 답 — 확인 동선 등록 필요(질문 문구: «사진 한 장을 줄여서 저장해 화면에 보여도 되는지, 하루 호출 한도»).
2. 켜는 시점·회차 상한.
3. 번호판 노출 처리 정책.
