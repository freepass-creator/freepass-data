# 3단계 보정 3 — 아이카 월렌트 (지휘통제실 → Codex, 2026-10-12)

대표 결정: 아이카 «월렌트» 탭은 ERP 에 «1개월»로만 반영한다(장기 대수와 별도 상품군). 지금 매퍼는 월렌트를 관측 전용(observationOnlyCount)으로만 센다.
형식(라이브 확인): 탭 «월렌트», 1행 머리글 «차종 | 1개월 | … » (A=차종 모델명, B=1개월 월 요금, 이후 비고 칸에 «월렌트 무보증», «*탁송비…» 등 메모). 값 «x» 또는 빈칸 = 그 상품 미제공(건너뜀). 차량번호 칸 없음.
할 일: 월렌트의 «B 칸이 숫자인 줄»을 상품으로 만든다 — product_group='MONTHLY_RENT', uid = 'RP004:MONTHLY:' + 차종명(공백·대소문자 정규화, 행 번호 금지; 같은 차종 2줄이면 중복 의심 표시), plate=null, terms = [{months:1, monthlyRent, deposit: 비고에 '무보증' 있으면 ZERO 아니면 UNKNOWN(보증금 확인 필요), mileage: '월렌트'}], 상태 = 판매 가능, 차명 = 차종 원문, 차종 4칸 비움+확인 필요. 대수 요약에 «월렌트 N»을 장기와 따로 표시. 번호미배정 집계에는 넣지 않는다. UNKNOWN 보증금이어도 편입 허용(대표 원칙: 판매 가능이면 원천과 같게, 모르는 칸은 확인 필요).
시험: 합성 월렌트 줄(숫자/x/빈칸/무보증 비고/중복 차종), 장기와 UID 충돌 없음, 두 번 실행 멱등. 결과 docs/SOURCE-ENGINE-RESULT3D-20261012.md. 네트워크·운영 쓰기 금지, 기존 미커밋 수정 유지.

## 추가(3E) — 신규 편입 문서 필수 칸 (라이브 적용에서 발견)
라이브 적용 결과 신규 편입 문서에 provider_name(공급사 표시 이름)과 policy_code 가 없어 ERP5 에서 공급사가 «?»로 나왔다(ERP5 는 provider_name 을 공급사 이름으로 쓴다). 지금은 운영 데이터를 직접 보정했다(같은 공급사 기존 문서의 최빈값). 엔진이 앞으로 편입할 때 스스로 넣게 하라: 같은 provider_company_code 의 기존 문서(listable 여부 무관)에서 provider_name 과 policy_code 의 최빈값을 구해 신규 문서에 채운다(기존 값이 없으면 공급사 코드→이름 설정 표를 쓰고, 그래도 없으면 편입 보류+사유 SUPPLIER_NAME_REQUIRED — 이름 없는 문서를 만들지 말 것). 시험: 합성 기존 문서 3개(최빈값 2)로 신규 편입 문서의 provider_name·policy_code 가 채워지는지, 기존 문서가 없으면 보류되는지, 기존 문서 갱신(UPDATE)에서는 이 두 칸을 덮어쓰지 않는지.
결과 문서에 3D+3E 함께 기록(RESULT3D). 이미 작업 트리의 미커밋 수정(gws 시트 읽기, 필드 경로 인용, 빈 기간 규칙, 판매 가능 검증 완화 등)은 유지한다.
