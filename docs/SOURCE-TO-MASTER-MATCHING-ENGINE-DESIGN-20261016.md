# 원천 → 차종 마스터 매칭 엔진 — 설계 한 장 (2026-10-16, 박대표 «차종 마스터 기반으로 정확하게 뽑아내야 한다» · «휘발성으로 끝나면 안 된다»)

상태: DESIGNED(구현 현황은 §0 표). 규칙의 출처는 ai-ops `docs/차종-기준-한장.md` — 이 문서는 구현 설계이며 규칙을 바꾸지 않는다(규칙 8: 마스터에 없는 이름은 만들지 않는다).

## 원칙 — 순서(박대표 2026-10-16): «일단 원문을 갖고 온 다음에 정제한다. 한번 갖고 온 건 정제되어 있어야 한다»
1. **가져오기(편입)가 먼저, 정제와 무관하게 완료**: 원문 저장·상품 문서 편입은 정제 실패·마스터 부족·마스터 읽기 실패로 막히지 않는다(10-14 «원문 먼저 → 편입 → 정제 사후 비차단» 유지, 지연 허용). 현재 구현: 마스터를 못 읽거나 검증 실패면 정제기가 null 이라 «정제 안 함 = 원문 형태로 편입»(`loadIdentityRefiner`), 정제 보류 문서도 편입·노출은 그대로.
2. **정제는 그 다음 단계**: 같은 회차의 후속(신규 편입은 편입 시점에 시도) 또는 다음 회차의 첫 단계로 큐처럼 처리한다 — 이미 편입된 문서는 `VEHICLE_IDENTITY` 사유가 남아 다음 회차에 순서대로 정제된다(회차 상한 100, 키 순서, 정제되면 사유 소멸). 정제 전 문서는 공개 피드에서 `refine_state=PENDING` + 원문 표기(2트랙, #692)로 나간다.
3. **이미 가져온 건 정제되어 있다 = 백필**: 기존 문서의 잔량을 공급사별로 줄여 가는 계획(아래 «백필 계획»)이며, 마스터가 없어 못 푸는 건은 마스터 보강 승인 큐(§5)로 간다.
4. **정제 지연 지표**: 신규 편입이 PENDING → REFINED 가 되기까지 걸린 회차 수(중앙값·최대)를 회차 보고에 싣는다(아래 «지연 지표»).

### 지연 지표(회차 보고 항목)
- `refine_latency_cycles`: 신규 편입 문서가 REFINED 가 되기까지의 회차 수 — 중앙값·최대·«N회차 넘게 PENDING» 건수. 계산을 위해 정제 시점 표식(`vehicle_refined_at`, 정제 쓰기 때 관측 시각)을 정제 쓰기에 함께 남기는 작은 변경이 필요하다(편입 시각은 `_direct_ingest_at`/최초 관측 시각 사용 — 칸 존재는 B3Q 확인 필요).
- `pending_total`·`pending_by_reason`: 보류 잔량과 사유별(백필 진행의 직접 지표).

## 1. 지금 막히는 곳과 «어떤 속성이 풀 수 있는가» (B3Q 계획서 기준, 손오공 346·전체 보류 954)

## 2. 매칭 입력과 확정 규칙
**입력**(원천 → 정규화): 원문 차명 토큰(밑줄·괄호·세대 접두 분해) · 연료(8종) · 배기량(cc) · 연식/최초등록 · 구동(원문 2WD/4WD/AWD 낱말 — 손오공 API 는 구조 필드 없음) · 인승(원문 «N인승») · 월 대여료(개월별) · 옵션 이름(단서).
**마스터 쪽**: 모델 → 세부모델(세대, `year_start~year_end`·별칭) → 트림(이름·별칭). 마스터 스키마(`usedcar-master-v1`)에 `fuelType`·`drivetrain`·`seats`·기본가격 이력 칸이 있으나 **정체성 대조 입력(IdentityMaster)은 이름·세대 연도·트림만 읽는다** — 속성 입력 확장과 칸 채움률 확인(B3Q 집계 필요)이 첫 작업이다.
**단계별 규칙**(후보를 «줄이는 방향으로만» 사용, 이름을 만들거나 바꾸지 않음):
1. 모델: 제조사(정본 표기·별칭) 일치 + 마스터 모델 이름/별칭 일치. 속성 점수 없음(이름만).
2. 세부모델(세대): 이름 부분 일치 후보 → 연식(최초등록 우선)이 세대 범위에 들어가는 후보만 → 변형(하이브리드/EV/PHEV) 증거(원문 낱말·연료 칸·E-TECH)와 충돌하면 제외 → **정확히 1개일 때만 확정**, 0 또는 2+ 면 보류.
3. 트림: 원문에 통째로 든 트림 이름(별칭)이 가장 긴 것이 유일 → 확정. 이름 근거가 없으면(원문에 등급 없음) 속성은 «후보 군을 줄이는 근거»로만 쓰고 군이 1개 트림이 될 때만 확정, 아니면 트림 비움.
4. **보조 단서(가격·옵션)는 확정 근거가 아니다**: 점수에만 반영해 후보 순서·후보 큐 메모에 쓴다. 자동 확정은 이름 근거 + 하드 속성 근거(연식·연료)가 서로 충돌하지 않을 때만.
5. 동점·모호·근거 부족은 전부 보류 + 사유 코드(현재 코드 체계 유지). 사람 입력 값(세부모델·트림)은 건드리지 않는다.

## 3. 입구 매핑과 합치기(하나의 «원천 → 마스터 매칭 엔진»)
`입구 매핑(제조사·모델: 마스터 이름일 때만, #706)` → `마스터 매칭(세부모델·트림, 위 규칙)` → `규격 검증(칸 형식, #701)` → `원산지(제조사 파생, #707)`를 같은 회차 안에서 순서대로 실행하고, 각 단계의 입력·출력·보류 사유를 한 줄 보고(§0 ④)로 합친다. 단계는 공급사별 허용 목록(기본 꺼짐 → 완료 기준 충족 후 기본 켜짐)으로 켠다.

## 4. 평가 세트(golden set)와 정확도 게이트
- **구성안**: 층화 무작위 — 손오공 노출 346대 중 200 + 아이카 50 + 이안카 50 = **300대**(보류 사유별 비율을 유지해 «자동 확정 가능»·«보류»가 모두 들어가게). 항목마다 사람이 확인할 칸 3개(모델·세부모델·트림), 출처 우선순위: 엔카 공개 화면 → 다나와 → 공급사 원문. **확인 대상 합계 300행 × 3칸**.
- **정답표 부담 줄이기**: 1단계로 손오공 100 + 아이카 20 + 이안카 20 = 140행(첫 정밀도 측정, 재현율 하한 산출) 먼저, 통과 후 300 으로 확대.
- **통계적 한계(정직하게)**: 자동 확정 표본에서 오류 0건이어도 95% 신뢰 하한이 약 `1 − 3/n`(3의 법칙)이다 — **정밀도 99% 를 입증하려면 «오류 0건인 자동 확정 표본이 약 300건» 필요**. 자동 확정이 140행 중 일부뿐이면 99% 입증이 안 되므로 평가 세트는 «자동 확정 후보»를 우선 표본으로 삼는다(보류 항목은 재현율 계산용).
- **지표**: 정밀도 = 자동 확정 중 정답 비율(목표 99%), 재현율 = 정답표 항목 중 자동으로 푼 비율. 현재 기준선: 손오공 노출 346 중 세부모델 정정 적용 가능 45(13%).
- **게이트**: 정답표(마스킹된 원문 + 정답)를 `tests/golden/identity-golden.v1.json` 으로 저장소에 두고, 매칭 규칙 변경 PR 의 시험이 정밀도 < 99% 면 실패(CI 차단). 정답표 변경은 대표·팀장 확인 기록과 함께.

## 5. 영구화 순환
`회차 보류` → `후보 큐 갱신(회차마다 candidates.jsonl: 묶음·사유·대수·마스킹 원문)` → `대표 예/아니오(시트)` → `마스터 반영(별칭·트림·세부모델 추가: 대표만, 결정 장부 id + 적용 digest + 되돌림 기록)` → `다음 회차 마스터 읽기 → 자동 정제`. 같은 묶음이 다시 나타나면 큐에서 «승인됨/거절됨» 으로 접어 되풀이 질문하지 않는다.
