# 공개 피드 «원문 표기·정제 상태» 2트랙 — 설계 한 장 (2026-10-16, 커맨드 센터 요청 / 박대표 결정)

상태: DESIGNED. 코드·쓰기 없음. 승인 뒤 구현·Codex 검토.
결정(박대표, 결정 장부): «프리패스 데이터에서도 정제를 하지만 ERP5 에서도 정제 안 된 원문을 끌고 갈 수 있게끔 2트랙». ① 기존 마스터 정제값 ② 미정제 차량은 공급사 원문 표기를 «정제 대기»와 함께 ERP5 가 끌어와 보여줌. 정제값이 있으면 항상 정제값이 이기고, 정제되면 즉시 전환.

## 1. 쓰기 경로가 아니다 — 읽기 서비스 응답에만 추가

문서에는 이미 원문이 있다(`car_name`, `원문.차명`). 새 문서 쓰기·새 칸 없음. 공개 피드 빌더(`src/api/public-product-feed.ts`)가 응답을 만들 때 **읽기 전용 파생값** 3칸을 더한다. 문서 쓰기 게이트는 필요 없고, 응답 추가 플래그만 둔다.
- 플래그 `FREEPASS_DATA_PUBLIC_SOURCE_RAW`: **기본 켜짐**(대표 결정), `0` 이면 끈다(되돌리기). Codex 검토 뒤 병합.
- 목록(list)·상세(detail) **둘 다** 나간다(원문은 짧은 한 줄이라 옵션처럼 목록에서 빼지 않는다).
- 정제되면 문서 칸(maker·model·sub_model…)이 바뀌므로 다음 응답부터 `refine_state` 가 자동으로 바뀐다(별도 전환 작업 없음; 응답 캐시 TTL 만큼 지연).

## 2. 추가 칸 (공개 피드 v1, 모두 선택 칸 — 기존 소비처 불변)

| 칸 | 값 | 설명 |
| --- | --- | --- |
| `source_raw_name` | 문자열 한 줄(≤120자) 또는 null | 공급사가 준 차명·세부 표기. 정제 칸(maker·model…)과 별개 |
| `refine_state` | `REFINED` \| `PENDING` | 정제 상태 |
| `refine_missing` | `['maker','model','sub_model']` 의 부분집합(빈 배열 가능) | 비어 있는 정제 칸. ERP5 가 칸별로 원문 대체 여부를 정한다 |

### `refine_state` 판정 (읽기 시점 문서 값만으로)
PENDING = **실제 값 기준**(커맨드 센터·B3Q 집계 반영 2026-10-16 — 표식만 보면 정제된 차량에 «정제 대기»가 붙는다):
1. `maker`·`model`·`sub_model` 중 하나라도 비어 있음(공백만도 비어 있음).
2. `sub_model` 에 밑줄(`_`) — «원문 형태».
3. 엔진 임시 표식(`vehicle_title_source === 'RAW_VEHICLE_TEXT'` 또는 `vehicle_review_required === true`)이 **있고** `sub_model` 이 원문 차명(`car_name`/`원문.차명`)과 공백·밑줄 무시하고 같음 — 표식은 보조 근거일 뿐이며, 표식이 남아 있어도 세부모델이 원문과 다르면(정제 완료, 예: G80 RG3·더 뉴 팰리세이드 LX2) REFINED.
그 외 REFINED. 판정 근거 칸은 이미 문서에 있는 것만 쓴다(추정·마스터 재대조 없음).
«차량 정보 확인 중» 은 문서에 저장된 문자열이 아니라 네 칸(제조사·모델·세부모델·트림)이 모두 비었을 때 ERP5 가 보여 주는 값이므로 **문자열 매칭하지 않는다**(네 칸 빈 값은 1번이 잡는다 — 노출 17).

## 3. `source_raw_name` 출처 매핑 (문서 `car_name` → 없으면 `원문.차명` 한 군데)

문서의 `car_name`·`원문.차명`은 각 원천 어댑터가 `vehicleText` 로 채운 값이다. 피드는 공급사별 분기 없이 이 두 칸만 읽는다.

| 공급사 | 어댑터 `vehicleText` 출처 |
| --- | --- |
| 손오공 RP012 | 상세 `carName`, 없으면 목록 `brand model detailName`(공백 합침). 원문이 `제조사_모델(코드)_연료…` 꼴이면 아래 표시용 가공 적용 |
| 이안카 RP031 | ONE 상세 `name` |
| 아이카 RP004 | 시트 `차종분류 + ' ' + 트림`(제조사 열은 vehicleText 에 안 들어감 — 정제 입구 매핑 설계 참조) |
| 오토플러스 RP023 | 시트 `차종(kind) 모델명`, 홈피 `bmname boname gradename` |
| 아이언 RP006 | 상세 제목 |
| 마음카 RP034 | 파일 차량명 칸 |
| F05 공유 시트 공급사 | 시트 `차명 원문` 칸 |

### 표시용 가공 (읽기 전용 파생, 문서·원문 불변)
1. 보이지 않는 문자(제어·서식·변형 선택자) 제거, 연속 공백 한 칸.
2. 밑줄 구분 `_` → 공백(예: `기아_K5(DL3)_가솔린` → `기아 K5(DL3) 가솔린`). 괄호 코드는 그대로 둔다(제거하면 의미를 잃는다).
3. 앞뒤 공백 제거, 120자 초과는 잘라서 `…`(원문 전체를 노출하지 않음).

### 개인정보·금지어 안전
공개 옵션 이름과 **같은 안전 필터**를 쓴다(`safeOptionName` 규칙 재사용, 길이 상한만 120): 전화·번호 꼴·금액 꼴·수수료/정산/고객 낱말 등이 걸리면 `source_raw_name` 은 null(피드 전체는 던지지 않음, `refine_state` 는 그대로 PENDING). 차량번호가 이름에 섞여 있으면 null.

## 4. ERP5 사용 규칙 (ERP·개발 몫)

칸별 우선순위: **정제 칸 값이 있으면 그 값**, 비어 있고 `refine_state === 'PENDING'` 이면 `source_raw_name` 을 표시하고 «정제 대기» 배지. 정제 칸이 모두 있고 `REFINED` 면 원문은 숨김(내부 참고용).
- `refine_missing` 으로 «제조사만 비었다» 같은 부분 상태를 칸별로 처리.
- `source_raw_name` 이 null 이고 PENDING 이면 «차량 정보 확인 중» 으로만 표시(원문 추측 금지).

## 5. ERP·개발에 필요한 허용 목록 변경 (한 줄 명세)

> ERP5 의 공개 피드 수용 허용 목록에 **선택 칸 3개**를 더한다: `source_raw_name`(문자열|null), `refine_state`(`REFINED`|`PENDING`), `refine_missing`(문자열 배열) — 칸이 없으면 종전 동작(정제 칸만 표시), 있으면 §4 규칙.

계약: `contracts/public-product-feed-v1.schema.json` 에 optional 속성으로만 추가(버전 번호 변경 없음, additionalProperties 기존 정책 유지).

## 6. 구현 순서·시험 (승인 후)

1. 피드 빌더: `sourceRawName(product)`·`refineState(product)` 순수 함수 + 플래그 + 계약 스키마 optional 속성.
2. 시험: 판정 3기준, 임시 표식 문서(sub_model=원문) → PENDING, 정제 후 REFINED 전환, 밑줄 가공, 괄호 코드 보존, 개인정보·번호·금액 꼴 → null, 길이 상한, 플래그 0 이면 칸 없음, list·detail 모두 포함, 기존 응답 불변(칸 추가 외).
3. 판매 시트(`sales-inventory-sheet`)에도 같은 파생값을 «원문 표기·정제 상태» 열로 붙일지는 별도 결정(이 설계 범위 밖).

## 7. 확정 사항 (커맨드 센터, 박대표 위임 2026-10-16)

1. 아이카 제조사는 `raw.headers`·`cells`(`raw.original['제조사']`)에 이미 보존돼 있어 **별도 저장 없이** 읽기 전용 접두로 쓴다(문서 `car_name`·어댑터 불변). 이미 제조사로 시작하는 원문에는 접두하지 않는다.
2. 자리표시자 문자열 매칭 없음(위 판정). 정제 뒤 표식이 남는 건수는 B3Q 가 필요 시 집계.
3. 구현: 공개 피드 빌더 읽기 전용 파생 + 플래그 `FREEPASS_DATA_PUBLIC_SOURCE_RAW`(기본 켜짐, `0` 이면 끔) + 계약 스키마 optional 속성 → Codex → B3Q 병합.
4. 부수 정정: 옵션·원문 표기는 자체 안전 필터를 거치므로 공용 금지값 검사(`assertNoForbiddenValue`, «%» 포함)에서 뺀다 — 안 그러면 «자외선 99% 차단» 같은 정상 값 하나가 피드 전체를 던진다(#687 잔여 수정의 완결).
