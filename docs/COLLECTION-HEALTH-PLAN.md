## B. 15분 수집이 실제로 도는가
- 실측: 공통 시트 갱신 워크플로의 예약(schedule) 실행은 최근 7일 27회(기대 672회, 준수율 약 4%), 성공 12·실패 15. 실행 시각이 UTC 21~01시(KST 06~10시)에 몰리고 10-11 00:27Z → 18:17Z 사이 17시간 공백. GitHub 예약은 부하 시 건너뛰거나 지연한다(워크플로 주석도 «지연 가능, 실제 관측시각으로 검증» 명시).
- 마지막 예약 실패(10-11 18:17Z) 원인: 적용 전 «매시 감사(daily-writer-guard) 최신 성공이 3시간 이내인가» 검사에서 불합격 → 적용 안 함. 즉 15분 적용이 매시 감사에 종속돼, 감사가 밀리면 같이 멈춘다. 10-07~09 연속 실패는 앞서 고친 3개 원인(전 보고).
- 안정 실행안(토큰 0 방식): ① 이 PC Windows 작업 스케줄러에 «감시 스크립트»(gh 읽기만, AI 토큰 0)를 15분마다 — 마지막 성공 예약 실행 시각·연속 실패 수·경과 분을 파일로 남기고 45분 초과 정지 또는 3연속 실패면 상황실 알림. ② 예약 신뢰성은 이미 만든 Cloud Scheduler → 비공개 OIDC 중계 → 허용 목록 dispatch 경로(현재 PAUSED, 대표 승인 항목)를 보조 트리거로 켜는 안. 수동 dispatch 는 검토 계획(reviewed_run_id 등)이 필요한 적용이라 «예약 전용 적용 모드»를 중계에서만 받는 입력으로 따로 정의해야 한다(별도 설계·검토). ③ 감사 종속 완화: 15분 적용의 가드 검사를 «최근 3시간 성공»에서 «가드 job 의 실패가 없고 마지막 성공 6시간 이내»로 조정(Claude 독립 검토 필요).
- 실행 증거: 마지막 성공 시각, 연속 실패 수, 24시간 준수율(실제 예약 실행 수/96)을 감시 파일과 점검표에 노출.
