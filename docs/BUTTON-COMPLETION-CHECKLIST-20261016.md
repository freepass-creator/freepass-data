대표 요구: «버튼을 딱 누르면 어떤 차가 오더라도 원문을 땡겨와서 정제해서 ERP5 에 들어가야 한다.» — «버튼»은 비유(커맨드 센터 정정). 핵심은 자동 흐름이며, 이 문서의 본체는 2절 체크리스트다. «지금 실행»(3절)은 점검용 선택 사항이다.

## 3. «지금 실행(수동 트리거)» 설계 — 선택 사항·낮은 우선순위

커맨드 센터 정정(2026-10-16): 박대표의 «버튼»은 비유이며 실제 버튼 개발이 아니다. 핵심은 «어떤 차가 들어오든 자동으로 원문 수집 → 정제 → ERP5». 따라서 아래는 운영 점검용 명령 한 줄(3-2)만 의미가 있고, 화면 버튼·요약 한 장(3-3)은 필요해질 때까지 만들지 않는다. 우선순위는 2절 체크리스트의 ✘/△ 해소다.

### 3-1. 목표와 불변 조건
공급사 지정 또는 전체를 한 번에 돌리고, 결과를 요약 한 장으로 돌려준다. 아래는 어떤 경로로 실행해도 **바뀌지 않는다**:
정시 회차 잠금(원천별 파일 잠금 — 겹치면 `LOCKED` 로 건너뜀) · 갱신 후 10분 신선도·SYNC_REGRESSED · 차량별 CAS·되읽기 · 20% 한도(`maxDowngradeRatio`) · 승인 게이트(자동 승인 스위치가 꺼진 원천은 계획만 만들고 쓰지 않음) · 새 쓰기 경로 기본 꺼짐. 수동 실행은 «새 승인»을 만들지 않는다.

### 3-2. 빠른 쪽: 명령 한 줄(오늘 가능) → 화면 버튼(다음 단계)
이미 있는 실행기 인자만 쓰면 새 코드 없이 된다:

```
node <runtime> --unattended --source RP012      # 공급사 하나
node <runtime> --unattended                      # 전체(정시 회차와 같은 경로)
```

- 수동 실행은 정시 예약이 없는 시각에 쓴다. 정시 회차가 이미 돌고 있으면 원천별 잠금이 `LOCKED` 로 막아 둘이 겹쳐 쓰지 않는다.
- **이안카**는 `--only-when-synced`(+`--watch-sync`) 때문에 «지금 눌러도 상류 갱신이 없으면 읽지 않는다»(UNCHANGED_SYNC). 이것은 의도다: 상류가 안 바뀌었는데 누르면 공급사 API만 소모한다. 요약에 «상류 갱신 대기» 로 명시한다.
- **마음카**는 파일이 새로 와야 의미가 있다(파일 경로 변수).
- 화면 버튼(어드민)은 같은 명령을 실행기 큐에 넣는 얇은 층이다. 빠른 길은 명령 한 줄이고, 버튼은 «공급사 선택 + 결과 요약 표시»만 얹는다 — 권한(누가 누를 수 있는가)은 ERP5·어드민 담당이 정한다.

### 3-3. 실행 결과 요약 한 장(출력 형식 제안)
공급사 한 줄씩: `상태(APPLIED/DRY_RUN/UNCHANGED_SYNC/LOCKED/HOLD/STOPPED) · 읽은 수 · 쓴 수 · 보류 수(사유 상위 3) · 입구 매핑 채움 수 · 정제 확정/보류 수 · 규격 위반 수 · 사진 연결/요청 수 · 소요 시간`. 합계 줄 하나와 «사람이 할 일 N건»(아래 4절) 한 줄을 맨 아래에 둔다. 이 요약은 이미 회차가 남기는 heartbeat·보고 값만 모아 만들며 새 쓰기가 아니다. **현재 코드에는 이 한 장 출력이 없다**(heartbeat 파일에 흩어져 있음) — 만들 일: 요약 집계 작업(읽기 전용) · DATA · 1일.

### 3-4. «눌러도 안 되는» 이유를 숨기지 않는다
버튼이 «다 됐다»를 말하려면 ③~⑥ 스위치가 승인 후 켜져 있어야 한다. 요약 맨 위에 «꺼진 단계: ③입구 ④정제 ⑤규격 …» 을 항상 표시해, 단계가 꺼진 채 «완료»로 읽히지 않게 한다.
