범위: DATA 는 **«드라이브 → 상품 반영»** 한쪽만. 업로드(상시 구동·방 감시)는 카톡 고도화 몫.

## 0. 경계


## 2. 번호 → 상품 문서 매칭 (끝 4자리·전체, 중복 방지)

1. 폴더명 첫 낱말에서 **전체 번호**(`\d{2,3}[가-힣]\d{4}`)를 꺼낸다. 번호 모양이 아니면 건너뜀(추정 금지).
2. 상품 문서는 **같은 공급사 안에서 전체 번호 일치**만 연결한다. 끝 4자리는 **표시·로그 전용**이며 매칭 키로 쓰지 않는다(끝 4자리는 공급사 안에서도 충돌한다).
3. 폴더 쪽 중복: 같은 번호 폴더가 둘 이상 → 그 번호 전체 보류(`ambiguous`, 사람이 합친 뒤 다음 회차).
4. 문서 쪽 중복: 같은 공급사·같은 번호의 활성 상품 문서가 둘 이상, 또는 0 → 보류(0은 «문서 없음»으로 보고, 폴더는 그대로 둔다. 다음 회차에 문서가 생기면 반영).
5. 다른 공급사 문서와는 절대 연결하지 않는다(공급사 폴더 ↔ 그 공급사 sourceId).
6. `folderMatchesPlate`(번호 뒤 숫자 접두 금지)로 등록 직전에 한 번 더 검증 — 등록 도구가 이미 하는 검증을 인입 계획에도 같은 함수로 맞춘다.
7. 기존 `photo_original_refs` 가 있으면 건너뜀(사람이 등록한 것 보존). 교체는 별도 승인.

## 3. 서류(등록증 등 개인정보) 제외 — 분류 규칙

사진 등록은 **«차량 사진이라고 확인된 직계 이미지»만**. 서류는 어떤 경우에도 refs 에 들어가면 안 된다(개인정보 노출 = 사고).

1. **구조 규칙**: 번호 폴더 **직계 이미지만** 읽는다. 하위 폴더(예: `서류`, `등록증`, `보험`)는 통째로 제외(현재 등록 도구 동작과 동일).
2. **이름 규칙**: 직계라도 파일명에 서류 표지(`등록증`·`자동차등록`·`서류`·`사업자`·`보험`·`계약`·`신분`·`면허`·`인감`·`명의`·`통장`·`견적`·`영수`)가 있으면 제외. 목록은 코드 상수 한 곳 + 시험으로 고정하고 늘리는 쪽으로만 바꾼다.
3. **확인 불가는 제외**: 이름이 비어 있거나 확장자가 이미지가 아니면(PDF 포함) 제외. 이미지 시그니처(JPEG/PNG/WEBP) 불일치도 제외.
4. **한 장이라도 서류 의심이 있는 폴더**: 의심 파일만 빼고 나머지를 등록하되, 제외 건수를 요약에 남긴다(조용히 삼키지 않는다). 의심 비율이 높으면(예: 절반 이상) 그 폴더는 통째로 보류 — 폴더가 서류 묶음일 가능성.
5. **이미지 내용 판독은 하지 않는다**(OCR·모델 판독 없음). 내용 기반 분류는 별도 결정(대표) 전에는 만들지 않는다. 따라서 **이름·구조로 못 거른 서류가 직계에 이름 없이 섞이면 막지 못한다** — 이 한계는 업로드 쪽 분리 규칙(카톡 고도화가 서류를 별도 하위 폴더로 보냄)에 의존한다. 이 의존을 명시 결정 항목에 올린다.
6. 아이카 «사용X» 표지는 상위 설계 §2 의 결정 대기(아이카는 허용표 제외 상태 유지).

## 4. 압축 (800px)

- 규격: 이안카 사본과 **같은 값**(최대 800px·JPEG 품질 72·mozjpeg, #641). 규격 상수는 한 곳에서 import — 두 군데 따로 두지 않는다.
- 이미 규격 이하(≤800px, JPEG)면 재압축하지 않고 그대로 복사(품질 손실 방지).
- 결과물: 우리 공유 드라이브 `<공급사 사본 루트>/<번호>/` 에 **별도 이름**으로 저장, 원본은 보존. `appProperties` 에 srcKey(원본 파일 id)·copySha256·규격 표기 → **재실행해도 같은 원본은 다시 만들지 않는다**(멱등).
- 상한: 파일당 8MB(서빙 규칙), 차량당 200장(승인 도메인 규칙), 회차당 차량 50대.
- 원본이 사진인지 시그니처로 확인한 뒤에만 디코드(이미지 폭탄 방지: 픽셀 수 상한).

## 5. 등록·쓰기 안전

- 대상: `photo_original_refs` **빈 칸 문서만**(등록 도구 규칙 그대로).
- 쓰기 전: 문서 백업(비공개 디렉터리), updateTime 조건, 쓰기 후 되읽기 일치 확인. CAS 충돌·대상 증가 시 그 건 건너뛰고 다음 회차.
- 삭제·덮어쓰기 없음. 철회는 기존 `publication_withdrawal` 규칙.
- 번호는 모든 출력에서 **끝 4자리만**. 드라이브 파일 id·경로 전체는 로그에 남기지 않는다(비공개 감사 파일에만).

## 10. 아이카(RP004) PILOT 경로 (커맨드 센터 2026-10-16: 카비에게 받은 사진 → freepasspics/아이카/<번호 차종>)

③ 전체(압축 사본·열거 어댑터)를 기다리지 않고, **기존 등록 도구에 «공급사 폴더 사본» 방법을 더해** 바로 DRY_RUN 할 수 있게 했다(원본 파일을 승인 refs 로 등록 — 서빙은 렌디션).
- 도구: `node scripts/ops/register-approved-photos.mjs --root <freepasspics/아이카 폴더> --method SUPPLIER_FOLDER_COPY --supplier RP004`(기본 DRY_RUN, `--apply` 는 승인 뒤).
- 가드: 사본 허용표(`FREEPASS_DATA_PHOTO_COPY_SUPPLIERS`)에 RP004 가 있어야 시작(RP031 은 이 방법 불가), 그 공급사 문서·사진 칸이 빈 문서만 쓴다, 파일명 서류 표지·«사용X»·폴더명 «사용X» 는 제외/보류, 번호는 같은 공급사 전체 번호 일치(번호 뒤 숫자 접두 금지).
- 아이카 번호 형식: 전체 번호 «109호NNNN»(숫자 2~3자리 + 한글 1자 + 숫자 4자리)은 폴더 매칭 키로 읽힌다. **지역 접두(예: «서울12가3456»)가 붙은 폴더명은 «번호 못 읽음»으로 건너뛴다**(추정하지 않음) — DRY_RUN 의 «번호 아님» 건수로 확인.
- 켜는 순서(운영): ① 빌드(`dist`) ② `FREEPASS_DATA_PHOTO_COPY_SUPPLIERS` 에 RP004 추가 ③ DRY_RUN 결과(올릴 대수·확인 필요) 확인 ④ `--apply --max 5` PILOT ⑤ 되읽기 MATCH 확인 뒤 나머지.
- «사용X» 의미는 아직 확정 전 → 안전 쪽(제외)으로 해석했다. 의미가 확정되면 이 표지 목록만 바꾼다.
