### 연동지도(ai-ops 4절)와 어긋난 곳
1. **F05 공급사 15곳의 products 는 F05 탭이 아니라 옛 개별 시트 탭 이름(`재고`·`빌린카재고` 등)을 출처로 달고 있다.** 연동지도는 «F05 공급사 탭→shared-sheet-daily→Data»로 그리지만, 상품 칸의 현재 출처 표시는 폐기 예정 F50~F69 경로다. 폐기 결정(10-10)이 실제 데이터에는 아직 반영 안 됨 — 개발 관제 판정 필요.
2. 연동지도는 손오공을 «F50 개별 시트 사용 중»으로 적었으나 실제 products 출처는 공급사 API(`sokrc`)이고 F50 이름은 쓰이지 않는다. 이안카는 반대로 옛 시트 출처 137대(전체의 40%)가 남아 있다.
3. 연동지도는 마지막 성공 «모른다»가 많다. 이 문서의 마지막 성공은 GitHub 실행 이력 직접 읽기이며, 개별 공급사 성공 시각은 여전히 모른다(실행 단위만 안다).
4. 규격이 F05 탭을 가정하는 연카·스위치플랜·에스에이는 F05 에 탭이 없고 데이터에는 41대가 남아 있다(주인 없는 상품 후보).
5. 연동지도의 F05 «공급사 직접 탭 입력»은 하루 1회 박제이고, products 갱신 경로는 ERP4 매시 회차다. 두 경로는 서로 다른 시각의 같은 원천을 읽을 수 있다.

## 2. 직접 확인 도구
- `scripts/supplier-origin-verify.mjs`: F05 탭을 `gws sheets +read`로 읽고(읽기 전용) products 를 Firestore REST 로 읽어 항목별 대조한다. 차량번호 마지막 4자리만 출력, 쓰기 없음, 시트 ID 는 `FREEPASS_SHEET_F05_ID` 환경변수.
  - 공급사 하나: `node scripts/supplier-origin-verify.mjs --supplier RP021 [--json] [--out 결과.json]`
  - 전수: `node scripts/supplier-origin-verify.mjs --all --out-dir <폴더>` (F05 15곳 약 10초). `--report-line` 은 점검 리포트용 한 줄 JSON.
  - 비교 항목: 차량번호 · 제조사 · 모델 · 세부모델 · 세부트림 · 외부색 · 연식 · 주행거리 · 배기량 · 연료 · 최초등록 · 차량상태 · 옵션 · 차명 원문 · 기간별(1/6/12/24/36/48/60개월) 월대여료·보증금. 보증금은 1·6개월=단기보증, 12개월 이상=장기보증 열로 비교한다.
  - 유형: `MISSING_IN_DATA` · `ONLY_IN_DATA` · `EMPTY_IN_DATA` · `EMPTY_IN_RAW` · `FORMAT_ONLY`(공백·쉼표·단위·날짜 자리수) · `NEAR_NUMERIC`(배기량 반올림 6% 이내) · `VALUE_DIFF` · `DUPLICATE_PLATE`.
- F05 밖 공급사(API·홈페이지·개별 시트)는 각 전담 세션이 만든 원본 JSON 을 `scripts/supplier-field-reconcile.mjs` 에 넣는다(같은 대조 라이브러리).
- 재사용 판정: ai-ops `읽기대조.mjs` 는 Firestore↔ERP5 공개 응답↔읽기 모듈 비교이고 `수집감시.mjs` 는 카톡 수집 감시라서 «공급사 원천↔데이터» 대조를 하지 않는다 → 새 파일은 정당화되며, 대조 라이브러리·Firestore 읽기 방식(`bogi`와 같은 REST)은 기존 것을 따른다.
- 한계: «원천»은 F05 탭의 정리된 값이다. 공급사 원문 그대로가 아니다(원문은 products `원문` 칸과 source_runs 에 보존). 그래서 제조사·모델·세부모델·세부트림 차이는 «정리 규칙/기준 버전 차이» 후보이지 데이터 오류 확정이 아니다.

## 3-1. 대조 범위·입력 형식·원인 분류 (대표 10-12 확정 목적)
목적: 프리패스 데이터가 상품별로 가진 **전 필드**를 원천과 필드별로 대조해 일치율·불일치 목록·원인으로 분류한다. 쓰기 없음, 고칠 건은 수정 PR 후보(`fixCandidates`).
- **비교 필드(원천에 있는 값)**: 제조사·모델·세부모델·세부트림·연식·외부색·주행거리·배기량·연료·최초등록·상태 원문·옵션·차명 원문, 기간별 월대여료·보증금(가격 행). 아이카는 원천이 갖는 칸만(제조사·연료·외장·Km·최초등록·배기량·배차상태·옵션·월렌트/36/48/60개월·장기보증).
- **데이터 완전성(원천 비교와 별도)**: 판매 중 상품의 칸별 채움률 — 기본·제원·상태·정책 연결·식별(UID)·가격 행·보증금·원문 보존 + **사진 수**(0장 대수, 평균). `dataCompleteness` 로 출력.
- **입력**: 기본은 products 를 직접 읽는다. 급한 작업 세션의 «상품 전수 조회(읽기)» 출력을 쓰려면 `--data-json <파일>` — **배열 또는 `{products:[…]}`/`{items:[…]}`**, 항목은 products 문서 필드를 디코딩한 값(`car_number`·`provider_company_code`·`listable`·`price`·`원문`·`image_urls`/`photo_link`·`policy_code`·`vehicle_uid` 등 저장된 이름 그대로). 이 형식이 아니면 알려 주면 맞춘다.
- **원인(5종)**: `COLLECTION_LAG` 수집 지연(데이터에 보존된 원문 `원문.전체` 가 현재 원천과 다름, 또는 원천에 새로 생긴 차) · `REFINEMENT_ERROR` 정제 오류(보존된 원문은 원천과 같은데 정리값이 다름 → 수정 PR 후보) · `SOURCE_CHANGE` 원천 변경(원천에서 차가 사라짐) · `SOURCE_ANOMALY` 원천 값 이상(숫자가 아닌 요금·주행거리 등) · `UNDETERMINED`(원문 없음 또는 가격처럼 가공 여부 확인 필요).
- **정상 변환은 일치로 센다**: 연료 HEV→하이브리드, 색 «검정색»→블랙·«스노우화이트펄»→화이트, 보증금 «무보증»=없음, 원천의 «-»는 빈칸, 배기량 반올림 6% 이내.

## 5. 정기 점검 편입
도구 공방이 점검 리포트에 붙일 출력은 `supplier-origin-verify --all --report-line` 의 한 줄 JSON 이다.
```json
{"kind":"supplier-origin-verify/v1","observedAt":"ISO","suppliers":[{"supplier":"RP021","tab":"빌린카","seconds":0.6,"rawVehicles":44,"dataVehicles":47,"commonVehicles":44,"vehicleCoverage":1,"fieldMatchRate":0.91,"fieldExactRate":0.0,"types":{"MISSING_IN_DATA":0,"ONLY_IN_DATA":3,"EMPTY_IN_DATA":2,"EMPTY_IN_RAW":4,"FORMAT_ONLY":500,"NEAR_NUMERIC":1,"VALUE_DIFF":88,"DUPLICATE_PLATE":0},"worstFields":[{"field":"price.1.deposit","compared":44,"matchRate":0.1}]}]}
```
- 경고 기준 제안: `vehicleCoverage` < 0.9 이거나 `MISSING_IN_DATA` > 0 이면 «수집 누락 후보», `fieldMatchRate` 가 직전 대비 5%p 이상 하락하면 «회귀». 판정 확정은 도구 공방.
- 주기 제안: 전수는 하루 1회(shared-sheet-daily 직후), 의심 시 공급사 단독 실행. 토큰 0, 약 10초.
- 예약 등록은 하지 않았다(지휘통제실 승인 필요).
- 시험: `tests/supplier-field-reconcile.node.mjs`·`tests/supplier-freshness.node.mjs` 11건.

## 6. 원문 칸 낡음 분리 (손오공 등, 지휘통제실 정정 반영)
손오공 수집은 정체가 아니다 — ERP4 매시 회차가 정리값(가격·상태·주행·사진)을 계속 갱신하고, products 에서 오래된 것은 `원문` 칸(09-04~09-11 백필 스냅샷)이다. 그래서 대조는 두 갈래로 따로 낸다.
- **정리값 ↔ 원천**: 기존 필드별 일치율·불일치 유형·원인.
- **원문 칸 ↔ 원천** (`rawColumn`): 필드별 `compared`·`stale`·`staleRate`, 그리고 `staleWhileRefinedMatches`(정리값은 원천과 맞는데 원문 칸만 낡은 수). 이 경우는 원인 `RAW_COLUMN_STALE`(원문 칸 낡음)로 센다 — 정제 오류도 수집 정체도 아니다. 정리값까지 원천과 다르면 기존대로 `COLLECTION_LAG`.
- 온라인 원천 일반 모드(손오공 ERP·이안카 ONE·아이언·오토플러스): `node scripts/supplier-origin-verify.mjs --supplier RP012 --raw-json <원천 읽기 결과 배열> --map <{데이터 칸: 원천 키}> [--stored-map <{데이터 칸: 데이터 원문 안 경로}>]`. `--map` 에 `car_number` 가 있어야 하고, `--stored-map` 의 경로는 `원문` 안의 점 경로(예 `전체.월렌트`, `사진`). 원천 읽기 결과는 각 전담 세션이 만든다(차량번호가 들어가므로 저장소 밖에 둔다).

## 7. 60개월 보증금 «확인 필요» 조사 (대표 질문, 2026-10-12 읽기 전용)
기준: 운영 ERP5 호환 읽기(`withCompatibilityDepositEvidence`)를 판매 중 474대 products 에 그대로 적용(쓰기 0).
- **60개월 가격 행이 있는 305대 중 보증금 KNOWN 206 · 미확인(UNKNOWN) 99.** 60개월 행 자체가 없는 169대(공급사가 60개월 상품을 안 파는 경우)는 보증금 대상이 아니다.
- 미확인 99 = **이안카 RP031 94 + 손오공 RP012 5**, 다른 공급사는 0.
  - 이안카 94: 사유 `IANCAR_PUBLISHED_DEPOSIT_EVIDENCE_UNVERIFIED`. 60개월만이 아니라 **기간 전부**가 미확인이다. 보증금 값(예: 150만 원)은 데이터에 있고 구조 검사도 통과하지만, 이안카 근거는 **15분 신선도 관문**(`IANCAR_PUBLISHED_DEPOSIT_FRESHNESS_SECONDS`)을 통과해야 확인으로 인정되는데 마지막 이안카 값 반영(`sourceSyncedAt`)이 101.7시간 전(10-08)이라 94대 모두 탈락. → «원천에 값이 있는데 우리가 못 가져온 것»이 아니라 **수집 중단으로 신선도 관문에 걸린 것**. 고치는 길: 이안카 수집 복구(다른 세션) — 복구되면 자동으로 KNOWN. 이안카 ERP 직접 대조는 비밀(계정)이 이 PC 에 없어 못 했다.
  - 손오공 5: 사유 `ZERO_DEPOSIT_FORBIDDEN_BY_PRODUCT_POLICY` — 저장된 보증금 0원인데 상품 정책(픽업구독 또는 보증금없음 불가 표시)이 0원을 금지 → **규칙 충돌**(원천 값 0 vs 상품 정책). 고치는 길: 해당 5대의 ERP 보증금 값 확인 후 정책 표기 또는 값 정정(손오공 ERP 직접 확인 필요, 비밀 승인 대기).
- 공통 시트·아이카(원천 직접 대조): 원천에 60개월 월대여료가 있는 차는 **전부 데이터에도 있고 60개월 행이 있다**(못 가져온 것 0). 60개월 행이 없는 차는 원천 시트의 60개월 칸이 비어 있는 경우다(웰릭스·리더스·센트로·에코·아이카 등) → 「공급사가 그 기간을 안 판다」이지 수집 누락이 아니다. 단 «판다/안 판다»를 공급사에 확인해야 할 후보: 60개월 칸이 비어 있는 공급사 상품은 빈칸 채우기 루프로 보낼 질문 후보다(질문 문안: «이 상품은 60개월 계약이 없는 것이 맞는가?»).
- 오토플러스(홈페이지): 가격 기간이 12·18·24·36개월(주행 2만/3만)뿐이라 60개월 행 없음 31대 전부. 아이언: 비표준 기간 다수(19~32개월, 48~72), 60개월 행 있는 10대는 KNOWN. 두 곳 모두 홈페이지 직접 대조는 못 했다.
- 내 그림자 측정(60개월 가격 행 719: KNOWN 452 · ZERO 267 · 미확인 0)과 다른 이유: ① 719는 판매 중이 아닌 상품까지 포함한 «가격 행» 기준이고 ② 화면(호환 읽기)은 이안카에 15분 신선도 관문과 상품별 근거 검사를 추가로 적용하며 ③ 보증금 0원은 정책 금지면 ZERO 가 아니라 미확인으로 내려간다. 즉 가격 행의 확정(KNOWN/ZERO)과 화면의 «보증금 근거 확인»은 다른 층이다.

## 9. 설계 한 장 — «직접 확인» 구조 (대표 정정 10-12: 옮겨 오는 게 아니라 그 순간 직접 확인)
목적: 차량번호 하나(또는 공급사 전체)를 넣으면 **그 순간 원천에서** 월대여료·기간별 가격·보증금(60개월 포함)·상태·사진 수를 읽어, 프리패스 데이터 값과 나란히 놓고 차이를 판정한다. 원천이 정답, 차이는 «우리 수집 오류 후보».
**원칙 5개**: ① 저장 없음 — 프리패스 데이터·시트·로컬 캐시에 쓰지 않는다(`--out` 증거 파일만 선택 사항, 저장소 밖, 요약만) ② 독립 경로 — 수집기가 만든 정제값·캐시·source_runs·RAW 를 입력으로 쓰지 않는다(데이터 쪽 값은 products 를 읽기만 하고 판정 기준은 항상 원천) ③ 매 호출 새로 읽기(재시도 외 캐시 없음) ④ 차량 하나 입력 → 즉시 결과(사람이 화면을 보는 방식 그대로) ⑤ 쓰기 0, 열쇠 출력 0.
| 공급사 | 직접 읽는 곳 | **재사용하는 부분**(요청·로그인 층만) | **건드리지 않는 부분**(수집 파이프라인) | 차량 하나 확인 시 얻는 것 |
| --- | --- | --- | --- | --- |
| 이안카 | ONE API | `createIancarOneApiClient` 의 `listVehicles`·`getVehicle`·`rates`(`/v1/vehicles/{id}/rates`) — 인증 헤더·재시도·타임아웃만 | `collectIancarOneVehicleList/FullFacts`(페이지 순회+지문+저장 준비), `buildIancarOneSourceBatch`, 15분 수집 job, 정제·상품 변환 | 상태, 기간×주행거리별 월대여료·보증금(60개월 포함), 사진 수, 원천 갱신 시각 |
| 손오공 | 손오공 ERP(sokrc.com API) | `sonogong-erp-reader` 의 로그인 JWT 갱신·목록 page/pageSize·`homepage/view` 상세 | 버킷 순회 적재·RAW 정규화·`sonogongSourceAdapter` | 상태, 기간별 월대여료·보증금(estimates 안), 사진 수 — **계정 필요(막힘)** |
| 아이카 | 별도 시트 | 기존 시트 읽기 경로(gws)와 `aicaSheetsGridReader` 의 칸 이름 | `collect-aica` 의 RAW 적재·귀속 검사 | 배차상태, 월렌트/36/48/60개월, 장기보증, 옵션 — 시트에는 사진·갱신 시각 칸 없음 |

**현재 구현(§8)과 이 설계의 차이 — 고칠 곳 3개**
1. 이안카 읽기가 `collectIancarOneVehicleList`(수집용 함수: 지문·페이지 순회)를 쓴다 → **요청 층(`createIancarOneApiClient`)만** 쓰도록 바꾸고, 차량 하나는 `listVehicles` 에서 번호를 찾아 `getVehicle`+`rates` 호출로 기간별 가격·보증금까지 읽게 한다(지금 목록에는 가격이 없다).
2. 아이언·오토플러스 홈페이지를 차량 하나로 좁혀 읽기(아이언은 목록→번호 찾기→상세 1회, 오토플러스는 브라우저가 필요해 자동화 한계).
3. 출력을 «차량 번호 하나 → 원천 vs 프리패스 데이터 나란히 + 차이 판정» 한 화면으로(지금 `read --plate4` 는 원천 쪽만 낸다).
**순서**: 승인되면 ① 이안카(요청 층만 쓰는 상세·요금 읽기) ② 아이카·아이언 차량 한 대 나란히 출력 ③ 손오공은 계정 등록 후 ④ 오토플러스 홈페이지는 브라우저 연결 방식 합의.

## 10. 직접 확인 구현 (승인: 대표 «추천대로 진행», 설계 §9 순서 ①②)
`node scripts/source-read.mjs compare <공급사코드> --plate4 XXXX [--homepage-plates 파일] [--json]` — 차량번호 끝 4자리 하나로 **그 순간** 원천을 읽어 프리패스 데이터 값과 나란히 놓고 항목별 판정(일치/일치(표기 차이)/차이/데이터 빈칸/원천 칸 없음). 같은 끝 4자리 상품이 여러 개면 각각. 원천이 정답. 저장 없음(임시 증거 파일은 읽은 뒤 지움), 수집 함수·정제·source_runs 를 거치지 않는다.
- 이안카(RP031): 기존 어댑터의 **요청 층만**(`createIancarOneApiClient` 의 `listVehicles`·`getVehicle`·`getRates`) — `src/jobs/read-iancar-source.ts --plate4`. 기간 × 주행거리별 월대여료·보증금(60개월 포함)·상태·사진 수·원천 갱신 시각까지.
- 아이카(RP004): 별도 시트 행(상태·연료·주행·외장·월렌트/36/48/60·장기보증). 시트에는 사진·갱신 시각 칸이 없다.
- 아이언(RP006): 홈페이지 목록→상세 1회(동시 2): 기간별 월대여료·보증금 문구·상태(게시/판매완료).
- 오토플러스(RP023): 시트 2탭 + 홈페이지 목록 파일 — 존재 여부와 데이터 판매 상태의 모순 판정(가격 상세는 아직 미구현).
- 손오공(RP012): 계정 등록 후.
실측 예(2026-10-12 16시대): 이안카 6235 — 원천 가능·사진 47장·기간별 요금 24개 vs 데이터 마지막 반영 09-08, 연식·주행거리 차이, 사진 0, 기간별 가격 없음. 아이카 4629(2대) — 원천(시트)에 둘 다 없음. 오토플러스 1484 — 시트·홈페이지 모두 없는데 데이터 판매중 → 공개 보류 후보. 아이카 5130 — 원천에 있고 데이터에 없음.
