# ERP / Sheet 상품조건 구조

## 핵심

FreePass Data의 상품조건 산출과 FreePass Estimate의 견적 계산은 별도 영역이다.

FreePass Data는 **한 상품 자체**에 대해:
- 어떤 조건을 선택할 수 있는지
- 기본 선택값이 무엇인지
- 그 선택값에 적용되는 정책/계약조건이 무엇인지
- 선택 결과 월대여료와 보증금이 얼마인지

를 산출한다.

FreePass Estimate는 그 상품조건 결과를 소비해서 고객별 Quote/견적서/저장/발송 같은 별도 업무를 담당한다.

## 입력과 결과를 분리한다

월대여료와 보증금은 원천 입력값을 그대로 ERP에 표시하는 개념이 아니다.

상품에는 먼저 다음 **입력 축**이 있다.

1. 차량/상품
2. 선택조건
   - 기간
   - 주행거리
   - 운전자 연령
   - 향후 기타 선택조건
3. 정책
   - 기본값
   - 허용범위
   - 가격/보증금 조정 규칙
4. 계약조건
   - 보험/면책/승계/중도해지 등

그리고 마지막에:

> **선택조건 + 정책 + 계약조건 → 최종 월대여료 + 최종 보증금**

이라는 결과가 나온다.

## ERP의 최초 표시값 = Default Preview

ERP 상품카드에 처음 보이는 가격도 단순한 첫 번째 가격행이나 최저가가 아니다.

명시된 기본조건을 선택한 뒤 상품조건 산출을 한 결과다.

예:
- 기본 기간: 36개월
- 기본 주행거리: 연 20,000km
- 기본 운전자 연령: 만 26세
- 보험: 기본 포함

이 기본 선택을 적용한 결과:
- 월대여료: 650,000원
- 보증금: 2,500,000원

이 값을 상품 목록에서 **미리보기 가격**으로 보여준다.

## 기본값 정책

기본값은 임의 추정하지 않는다.

- 기간이 여러 개인 경우: `default_term_months` 필요
- 기본 주행거리: `annual_mileage`
- 기본 운전자 연령: `basic_driver_age`
- 기타 선택축이 생기면 해당 축의 명시적 default가 필요

단, 기간 선택지가 하나뿐이면 그 하나를 기본값으로 사용할 수 있다.

"첫 행", "가장 싼 가격", "가장 짧은 기간" 같은 UI 편의 추론을 정본 정책으로 사용하지 않는다.

## 조건 변경

사용자가 ERP에서 조건을 바꾸면 같은 상품을 다시 산출한다.

예:
- 36개월 → 24개월
- 20,000km → 30,000km
- 만 26세 → 만 21세

각 변경은 최종 월대여료/보증금에 영향을 줄 수 있다.

기간/주행거리처럼 원천 가격행이 명확히 존재하면 그 행을 기준으로 산출한다.
연령 등 추가 가감 규칙이 필요한데 아직 typed policy가 없으면 잘못된 최종가격을 보여주지 않고
`*_PRICE_RULE_REQUIRED` 상태로 막는다.

## Google Sheet와 ERP의 역할 차이

### Google Sheet / 관리 데이터
검수와 원천관리를 위해 **가격 Basis**를 펼쳐 보관할 수 있다.

예:
- 24개월 / 20,000km / 기준 월대여료 700,000 / 기준 보증금 3,000,000
- 24개월 / 30,000km / 기준 월대여료 760,000 / 기준 보증금 3,500,000
- 36개월 / 20,000km / 기준 월대여료 650,000 / 기준 보증금 2,500,000

이것은 산출의 기반 데이터다.

### ERP
ERP가 사용자에게 우선 보여주는 것은 Basis 전체가 아니라:
- 선택 가능한 조건
- 기본 선택값
- 현재 선택값
- **현재 선택을 적용한 최종 월대여료/보증금**

이다.

조건을 변경하면 결과를 다시 산출한다.

## FreePass Estimate와의 경계

이 로직에는 다음을 넣지 않는다.
- 고객별 Quote ID
- 견적 저장/수정 이력
- 견적서 문서
- 고객 선택 저장
- 견적 발송
- Provider 견적 routing

그것들은 FreePass Estimate 영역이다.

FreePass Data의 책임은 **상품이 특정 조건에서 얼마인가**까지다.
