# ERP / Sheet 상품조건 구조

## 핵심

대여료 한 줄은 단순한 금액이 아니다.

> **기준 대여료 = 금액 + 그 금액이 성립하는 조건 범위**

예를 들어 월 700,000원이 등록되어 있다면 시스템은 동시에 다음을 알아야 한다.

- 24개월 조건
- 연 20,000km까지의 기준
- 기본 운전자 연령 만 26세 이상
- 연령 상한 만 70세 이하
- 연령 하향 가능 시 만 21세까지
- 추가운전자 기본 0명, 최대 1명 추가 가능
- 개인 운전자 범위 본인+직계가족
- 면허 1년 이상
- 보험료 포함
- 정비 미제공

그래야 700,000원이 어떤 조건의 가격인지 설명할 수 있고, 조건이 바뀌었을 때 어느 정책으로 얼마를 조정해야 하는지 알 수 있다.

## 현재 정책에서 월대여료를 직접 결정하는 세 가지 조정축

기존 ERP4 정책 정본의 Sales Layer를 확인한 결과 다음 세 항목은 명시적으로 월 대여료를 결정하는 계산 입력이다.

1. mileage_upcharge_per_10000km
   - 약정 주행거리 1만km 상향당 월 대여료 가산
   - 정액 또는 대여료의 비율일 수 있음
2. age_lowering_cost
   - 기본 운전자 연령보다 낮은 연령을 선택할 때 월 대여료 가산
   - 정액 또는 대여료의 비율일 수 있음
3. additional_driver_cost
   - 추가운전자 1인당 월 대여료 가산
   - 정액 또는 대여료의 비율일 수 있음

이 세 값은 계약 후 별도 청구금이 아니라 최종 월대여료를 만들기 위한 입력값이다.

## 기준 대여료의 적용범위를 설명하는 정책

### 주행
- annual_mileage: 기본 약정 주행거리
- max_annual_mileage: 최대 선택 가능 주행거리(값이 있을 때)
- mileage_upcharge_per_10000km: 상향 가산 규칙

### 연령
- basic_driver_age: 기준 대여료에 포함되는 최소 연령
- driver_age_lowering: 추가비용을 내고 낮출 수 있는 최소 연령
- driver_age_upper_limit: 계약 가능한 최대 연령
- age_lowering_cost: 연령 하향 시 월 가산 규칙

만 26세 이상 기준 가격은 26세만의 가격이 아니다. 예를 들어 상한이 만 70세라면 만 26~70세 범위는 같은 기준가격이 적용되고, 21~25세처럼 기본 연령 아래로 내려갈 때 연령 하향 정책이 작동한다.

### 운전자
- personal_driver_scope
- business_driver_scope
- additional_driver_allowance_count: 몇 명까지 추가 등록 가능한지
- additional_driver_cost: 추가 1인당 월 가산 규칙
- license_period: 면허 경력 자격

additional_driver_allowance_count는 기존 정책 정본에 실제 존재한다. 따라서 기준가격은 어떤 운전자 범위이며 추가운전자를 몇 명까지 붙일 수 있는가를 가격 컨텍스트에 같이 보존한다.

### 상품 포함 범위
- insurance_included
- maintenance_service

이 값들도 기준 대여료가 어떤 상품 구성의 가격인지 설명하는 컨텍스트다.

## 가격 Basis와 최종 Result

Google Sheet/Canonical의 Basis는 기간 + 적용조건범위 + 기준 월대여료 + 기준 보증금이다.

ERP의 Result는 현재 선택조건 + 정책 조정 → 최종 월대여료 + 최종 보증금이다.

따라서 Basis와 Result를 같은 필드로 취급하지 않는다.

## 가격 선택 우선순위

1. 사용자가 선택한 조건과 정확히 맞는 명시 가격행이 있으면 그 행이 우선
2. 정확한 가격행이 없고 정책상 조정 가능한 축이면 기준행 + 정책 가산으로 산출
3. 필요한 가산 규칙의 의미/단위가 아직 정본화되지 않았으면 최종가격을 지어내지 않고 HOLD

예:
- 24개월/3만km 가격행이 실제 있으면 그것을 사용
- 36개월/2만km만 있고 3만km 가격행이 없으나 1만km 상향 요금 정책이 있으면 그 정책으로 산출 가능
- 단 정액/정률 해석이 정본화되지 않았으면 계산하지 않음

## 보증금

보증금도 최종 Result다.

기간/대여료에 따라 보증금 규칙이 달라질 수 있으므로, 월대여료가 정책 가산으로 바뀌었는데 보증금 산정 규칙이 월대여료 연동형인 상품이라면 기준행의 보증금을 그대로 보여주면 안 된다.

현재 ERP4에는 실제로 월 대여료 × 연수(최대 ×3), 월 대여료 ×2, 기간별 ×3/×6 같은 보증금 정책 구현이 존재한다.

따라서 FreePass Data에서는 이 규칙의 authority를 명확히 가져온 뒤, 최종 대여료 산출 후 최종 보증금까지 산출하는 순서로 가야 한다.

## FreePass Estimate와 경계

여기까지는 상품조건 산출이다. 고객 견적 저장/발송/Quote ID/견적서는 FreePass Estimate 영역이다.
## 원천 가격행의 조건 귀속

기간별 대여료와 보증금은 가져온 즉시 가격만 저장하지 않는다.
각 가격행에 그 금액이 성립하는 조건과 근거를 함께 귀속한다.

근거 상태:
- SOURCE_PRICE_KEY: 가격 키 자체가 기간/주행거리/반납·인수 조건을 명시
- CANONICAL_PRICE_TERM: 정규화된 PriceTerm에 값이 있으나 원천 키 직접 증거는 아님
- LINKED_POLICY_FACT: 같은 상품에 연결된 정책 사실에서 조건을 확인
- UNRESOLVED: 어떤 원천/정책에서도 해당 기준조건을 확인할 수 없음

예:
- source:24_2만 → 기간 24개월, 주행거리 20,000km는 SOURCE_PRICE_KEY
- basic_driver_age=만 26세 이상 → LINKED_POLICY_FACT
- property_compensation_limit=1억원 → LINKED_POLICY_FACT
- 추가운전자 기본 포함 수가 원천/정책에 없음 → UNKNOWN

가격행은 UNKNOWN 조건이 하나라도 있으면 PARTIAL로 표시한다.
UNKNOWN을 프리패스 기본값으로 덮어 가격의 원천 조건처럼 보이게 하지 않는다.

월대여료와 보증금도 각각 출처를 구분한다.
보증금 숫자 또는 산정근거가 확인되지 않으면 월대여료가 확정되어 있어도 보증금은 별도 UNRESOLVED다.

이 조건 귀속은 이후 가격 산출의 기준점이다.
사용자가 조건을 바꾸면 어떤 기준조건에서 출발했는지 확인한 뒤 변경 규칙을 적용해야 한다.
## 역방향 정책 매칭

가격행의 조건 귀속은 정책에서 가격으로만 흐르지 않는다.
원천 가격행에서 독립적으로 확인된 조건이 있으면 같은 공급사의 정책 후보와 역으로 대조할 수 있다.

예:
- source:24_2만 → 24개월 / 연 20,000km 확인
- 같은 공급사의 정책 후보 A: 연 20,000km / 만26세 / 대물 1억
- 같은 공급사의 정책 후보 B: 연 30,000km / 만26세 / 대물 2억
- 독립 증거인 연 20,000km와 유일하게 맞는 A만 남으면 A를 UNIQUE_MATCH로 귀속
- 이후 A의 보험/연령 조건은 MATCHED_POLICY_FACT로 가격행에 채울 수 있음

안전 규칙:
- 다른 공급사의 정책은 후보에서 제외
- 이미 정책에서 가져온 값을 다시 정책 매칭 근거로 쓰지 않음(순환추론 금지)
- 후보가 2개 이상이면 AMBIGUOUS
- 후보가 없으면 NO_MATCH
- 독립 조건 증거가 없으면 INSUFFICIENT_EVIDENCE
- UNIQUE_MATCH일 때만 미확인 조건을 정책값으로 보강

즉 UNKNOWN을 무조건 유지하는 것이 목적이 아니라, 근거 있는 매칭이 가능한 UNKNOWN은 해소하고 근거가 없는 UNKNOWN만 남긴다.
