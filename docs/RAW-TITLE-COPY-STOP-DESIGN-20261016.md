# 원문 차명 sub_model 복사 중단 — 설계 한 장 (2026-10-16, 대표 정정 10-15)

대표: «원문을 거는 게 아니라 목록 카드 맨 위에 세부모델을 걸기로 했고 그런 설계가 있는데, 세부모델 칸에 원문이 들어가 원문이 보여 버리는 것.»
상태: DESIGNED. 코드 변경 없음. 승인(결정) 뒤 구현·Codex.

## 1. 사실 (코드 기준)
| 위치 | 동작 | 상태 |
| --- | --- | --- |
| `nativeCycleFields`(`src/infra/source-cycle-firestore.ts`) 신규 편입(`isNew`) | `maker=''`, `model=''`, **`sub_model = r.vehicleText`**, `trim_name=''`, `vehicle_review_required=true`, `vehicle_title_source='RAW_VEHICLE_TEXT'`, `원문.차명` 보존 | **유일한 활성 복사 지점** |

## 2. 목표 규칙
- `sub_model`(·`maker`·`model`·`trim_name`)에는 **차종 마스터에서 하나로 특정된 값만** 들어간다. 특정 못 하면 빈칸 + `vehicle_review_required=true` + `vehicle_title_source='RAW_VEHICLE_TEXT'`(표식 이름 유지) + 원문은 `원문.차명`·`car_name`·raw 에 그대로 보존.
- 화면(ERP5)은 세부모델 칸이 비어 있고 표식이 있으면 «차량 정보 확인 중»만 보인다(ERP·개발 몫, 원문 폴백 없음).

## 3. 단계 (순서가 안전의 핵심)
1. **ERP5 제목 폴백 배포(ERP·개발)**: 세부모델 칸이 비면 «차량 정보 확인 중». 이것이 먼저다 — 아니면 비운 뒤 «차량 정보 확인 필요»가 거친 문구로 나간다.
2. **정체성 정제 첫 묶음 적용·되읽기(손오공 등)**: 마스터로 특정되는 문서가 먼저 승격된다.
3. **엔진 변경 PR(③ 신규 편입)**: `nativeCycleFields` 의 `sub_model: r.vehicleText` → `sub_model: ''`. 동시에 `rawTitleBackfillFields` 와 시험 삭제. 효과: 새 문서는 처음부터 원문이 칸에 안 들어간다. `car_name`·`원문.차명` 은 그대로.
4. **기존 복사본 비우기(② 아래 안 A)**: 승격되지 않고 남은 문서만.
5. 공개 카탈로그로 확인(세부모델 «_» 포함·원문형 건수, 비어 있는 노출 건수 — 비운 대수와 일치).

## 4. 기존 복사본 비우기 — 두 안 비교와 권고
**안 A — 별도 비우기 작업(권고)**: 계획(읽기 전용) → 승인 digest → 적용.
- 대상(전부 충족): 표식 `vehicle_title_source='RAW_VEHICLE_TEXT'` 또는 `vehicle_review_required=true`; `maker`·`model`·`trim_name` 빔; `sub_model` 이 `원문.차명`(또는 `car_name`)과 **정확히 같음**(사람이 고친 값 제외); 정산 잠금·철회 표식 없음.
- 쓰기: `sub_model=''` 한 칸 + 되돌림용 기록 `sub_model_cleared_prior`(이전 값·시각·실행 id). 표식·`원문`·`car_name` 불변.
- 안전: 문서별 updateTime 조건(CAS)·백업(비공개 디렉터리)·한 건씩 되읽기·계획 digest 승인·회차당 상한(예: 100)·롤백(백업 값을 CAS 로 복원).
- 장점: 정체성 적용기의 불변식(`to` 는 활성 마스터 하나)을 건드리지 않는다. 실패해도 정제와 독립적으로 롤백.

**안 B — 정제와 함께 비우기**: 정체성 적용기에 «`to` 가 빈 값» 허용을 넣어 한 계획에서 처리.
- 단점: 적용기의 «마스터 하나로 특정» 불변식을 약화시키고, 정제 실패·부분 적용과 비우기가 한 롤백에 묶인다. 권고하지 않는다.

## 5. 영향받는 소비처(비우기·③ 전에 확인)
ERP5 카탈로그 제목, 공개 피드 `sub_model`, F01/F03 시트 투영, 카톡 카탈로그 참조. 세부모델 칸이 빈 상품을 «확인 중»으로 다루는지 각 소비처 담당이 확인해야 한다(특히 시트 투영이 빈 세부모델을 오류로 보지 않는지).

## 6. 하지 않는 것
- 원문(`원문.차명`·`car_name`·raw) 삭제·수정.
- 마스터에 없는 이름을 지어 채우기, 추측 매칭.
- 사람이 고친 값·승인된 값의 덮어쓰기.
