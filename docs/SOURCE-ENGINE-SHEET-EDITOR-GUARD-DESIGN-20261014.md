# 원천 시트 편집자 가드 설계안 (2026-10-14, 읽기 전용 설계 — 코드·설정 변경 없음)

## 배경

공개 저장소 이력에 남은 시트 ID 때문에, 엔진 원천 시트 4곳(F05·F53·F67·이안카_프리패스)이 «링크를 아는 누구나 편집»인 채로
노출돼 있다(B3Q 확인 2026-10-14). 공유 설정 축소는 공급사 입력 흐름이 링크 편집에 기대는지 확인 뒤 대표가 결정한다.
그 사이 엔진이 변조된 값을 정상 갱신으로 받아들이지 않게 하는 완화책이다. 대량 변조는 이미 하향 비율·가격 drift·백업·되읽기가 막지만
소량 변조(가격 몇 건)는 정상 갱신과 구분되지 않는다.

## 원칙

- 편집자를 «알려진 계정 / 익명·외부»로 나눠 **회차를 멈추는 대신 신뢰 수준을 낮춘다**. 공급사가 로그인 없이 입력하는 시트는 익명 편집이
  정상일 수 있으므로 익명 = 차단으로 두면 전 원천이 멈춘다.
- 읽을 수 없으면(권한·한도) 차단하지 않고 UNVERIFIED 로 두고 알림 한 번. 신선해 «보이게» 하는 방향의 폴백은 없다.
- 판단 근거는 Drive 편집 이력(revisions.list) 하나. 셀 값은 보지 않는다.

## 입력 증거

시트마다 마지막 회차 이후의 revision 목록: `lastModifyingUser`(없으면 익명), `modifiedTime`.
회차 상태 파일에 `lastRevisionId`·`lastCheckedAt` 를 저장해 증분만 본다(회차당 시트당 호출 1~2회, 시간당 약 4~8회).

## 판정

| 신뢰 수준 | 조건 | 동작 |
|---|---|---|
| KNOWN | 이번 증분의 편집자가 모두 허용 목록(엔진 서비스 계정·알려진 공급사 계정·회사 도메인) | 현재와 같음 |
| UNVERIFIED | 익명·외부 도메인 편집자 포함, 또는 이력을 못 읽음 | 아래 «강화 가드» 적용 |
| SUSPECT | 짧은 시간에 익명 편집 다수 + 가격·상태 변경 대량 | 원천 HOLD(쓰기 0), 커맨드 센터 경보 |

### 강화 가드(UNVERIFIED 일 때만)

1. **변경 건수 상한**: 한 회차 UPDATE·DOWNGRADE 합이 노출 대수의 10% 와 절대 10건 중 큰 값을 넘으면 쓰지 않고 보류.
2. **가격 변동 상한**: 월 대여료 ±30% 를 넘는 변경은 보류(다음 회차에도 같은 값이면 2회 연속 확인 후 적용).
3. **보증금 하향 보류**: KNOWN/ZERO 로의 하향은 2회 연속 같은 값일 때만(이미 UNKNOWN 보존 규칙과 같은 방향).
4. **출고불가 → 출고가능 복귀 지연**: 2회 연속 확인 후 재노출.
5. 위 보류는 사유 코드(`EDITOR_UNVERIFIED_<가드>`)와 건수만 기록하고 연속 실패로 세지 않는다(UPSTREAM_STALE 와 같은 소프트 보류).

## 구현 위치(안)

- 포트: `SheetEditorEvidence { read(sourceId): Promise<{ trust: 'KNOWN'|'UNVERIFIED'|'SUSPECT'; editors: Array<{ kind: 'ENGINE'|'KNOWN'|'EXTERNAL'|'ANONYMOUS'; count: number }>; checkedAt: string }> }`.
- 어댑터: `src/adapters/sheet-editor-evidence.ts`(gws drive revisions 읽기, 허용 목록은 환경값·비공개 설정; 저장소에 계정 목록을 두지 않음).
- 계획: `planSourceCycle` 에 `config.editorTrust` 를 받아 UNVERIFIED 일 때 위 가드를 blocker/warning 으로 적용(기존 비율 가드와 같은 자리).
- 런타임: 회차 읽기 직전에 한 번 증거를 읽고 plan 에 전달. 증거 읽기 실패는 회차를 막지 않는다.

## 시험 목록

1. 모두 KNOWN → 기존 시험과 동일.
2. 익명 편집 포함 + 가격 +50% 한 건 → 보류(사유 코드, 연속 실패 0).
3. 같은 값이 2회 연속 → 두 번째 회차에 적용.
4. 익명 편집 + 변경 건수 상한 초과 → 전체 보류.
5. 이력 읽기 실패 → UNVERIFIED 로 처리, 회차는 진행, 알림 한 번.
6. SUSPECT → 쓰기 0, 백업·되읽기 경로 호출 없음.

## 한계

- 익명 편집자는 «누구인지» 알 수 없다: 이 가드는 변조를 식별하지 못하고 **영향 범위를 제한**할 뿐이다.
- 정상 공급사가 익명으로 입력하면 대량 변경 때 보류가 늘 수 있다(첫 적용 전 B3Q DRY_RUN 으로 건수 확인).
- 근본 해결은 공유 설정 축소와 ID 교체(별도 대표 결정)이다.

## 부록: 숨김 «정책원문·정책확인·계좌번호 머리» 탭의 비공개 시트 분리 검토 (2026-10-14, 읽기 전용 정리)

- **보호가 안 되는 이유**: 시트 권한에는 숨김 탭 구분이 없다. 링크 공개 상태에서 reader 이상이면 API·내보내기·사본 만들기로 읽을 수 있고, writer 면 숨김 해제·수정도 된다. 링크를 reader 로 낮춰도 해결되지 않는다 — 분리가 필요하다.
- **코드가 숨김 탭을 읽는 곳**: 엔진 회차는 숨김 탭·숨김 행을 제외하고 공급사 탭만 읽는다(영향 없음). «정책원문» 탭은 사람이 참조하는 보존용 텍스트이며 코드가 읽지 않는다. «정책확인» 탭은 `src/jobs/export-sheet-blank-fill-input.ts`(CHECK_TAB)가 읽는다(MATCHED 줄 → 정책코드·차량번호 대조). 계좌번호 칸은 2026-10-04 `no-account` 규격으로 공동 입력시트에서 제거 결정이라 머리 탭에 남은 것이 있는지 확인이 필요하다.
- **이전 시 영향**: 엔진·공급사 입력 = 없음. 빈칸 보충 작업(export-sheet-blank-fill-input) = 정책확인 탭 위치(시트 ID·탭 이름)를 환경값으로 바꾸고 계약·시험을 고쳐야 한다. 정책원문 = 사람이 참조할 비공개 시트 접근 권한(내부 사용자)만 주면 된다.
- **절차(안)**: ① 숨김 탭 목록·머리 이름만 읽기 전용으로 확인 ② 내부 사용자 한정 비공개 시트를 새로 만들어 숨김 탭을 이동 ③ 원본 시트에서 해당 탭 삭제(백업 후) ④ blank-fill 작업의 탭 참조를 환경값으로 교체 ⑤ 새 시트 ID 는 저장소에 두지 않는다(환경값/비공개 설정).
- **결정 필요**: 대표/OPS·개발 — 공유 설정 축소·ID 교체 결정과 묶어서 진행하는 것이 한 번에 끝난다(ID 를 바꾸면 숨김 탭도 새 시트에 나눠 담을 수 있음).
