# 이안카 사진 — 어떻게 할지 (읽기 전용 조사 한 장, 2026-10-14, DATA)

> 질문: 대표 «이안카 사진을 어떻게 할지». 코드 변경 없음. 근거는 저장소 코드·문서(`docs/IANCAR-ONE-API.md`, `src/adapters/iancar-one-api.ts`, `docs/IANCAR-PHOTO-GATE-ROLLOUT.md`)이며, **이 세션은 ONE API 키가 없어 실호출·상태코드 측정은 하지 않았다** — 실측 칸은 «문서 기록»으로 표시했다.

## ① ONE API 사진 필드
- 목록: 대표사진 참조가 있을 수 있음(문서 기록: 목록 사진 참조 보유 52대, 상세 샘플 1대에 사진 47개 — 2026-10 초 표본, 전수 아님).
- 상세 `GET /v1/vehicles/{vehicle_id}`: `photos[]` 배열. 항목 키 이름만: `photo_id`(문자열, ≤2048자, 중복 없음), `url`(문자열), `representative`(불리언, 대표는 최대 1개). 배열 상한 200장(코드 상한).
- 형식: **직접 공개 URL이 아니다.** `url` 은 ONE API 원점의 «상대/절대 경로»이고 `/v1/vehicles/{vehicle_id}/photos/{photo_id}` 와 정확히 같아야 하며 쿼리·해시·계정 정보가 없다(코드가 검사). 즉 서명 URL 이 아니라 **API 경로**다.
- 사진 본문: `GET /v1/vehicles/{vehicle_id}/photos/{photo_id}` — 문서 기록: 인증된 요청 HTTP 200·image/jpeg·약 490KB(표본 1장).

## ② 브라우저에서 직접 열리는가 — 아니오
- 사진 경로도 **`Authorization: Bearer <API 키>` 가 필요**하고 «사진 참조는 24시간 유효»(문서). 브라우저가 직접 로드하려면 키가 브라우저로 나가야 하므로 불가(문서 원칙: 브라우저/ERP.com 에 ONE API 키를 넘기지 않는다).
- 만료: 24시간. Referer·쿠키 조건은 문서에 없음(인증 헤더가 전부). 무키 요청은 목록에서 401 + `WWW-Authenticate: Bearer` 확인(문서), 사진 경로도 같은 인증.
- 상태코드 샘플: 미측정(키 없음, 공급사 호출 금지). 필요하면 B3Q 가 `scripts/iancar-photo-gate-measure.mjs` 로 측정(출력은 개수·번호 끝 4자리).

## ③ 지금 ERP5 가 사진 0/93 인 이유
1. **의도된 끊김**: 대표 10-12 «이안카 사진 끊기» → 이안카 노출 문서의 사진 칸을 `image_kind=PHOTO_PENDING`(image_urls 비움)으로 표시하고 화면은 «사진 준비 중»(`iancarPhotoPendingPatch`). 배포 /api/catalog 의 이안카 93대가 imageUrl 없음 + photoPending 인 이유.
2. **원인(끊기 이전)**: 이안카 상세의 «사진을 불러오지 못했습니다» — 서버 경유 사진 요청이 47대 중 1대만 200(이안카 서버 응답 속도·호출 한도, `IANCAR-PHOTO-GATE-ROLLOUT.md`). ID 게이트(`IANCAR_PHOTO_ID_GATE_SUPPLIERS=RP031`)는 코드 준비·기본 꺼짐, 켜는 것은 승인 사항이었다.
3. 이안카 앨범 ID 가 바뀌면(ONE 재발급) 등록 ID 집합이 달라져 404 — 수집이 ID 목록을 함께 갱신해야 한다.

## 추천: **b 안(압축 사본 → 번호 폴더 → 승인 refs), 파일럿 후 확대**
근거 3가지:
1. a 는 키 때문에 불가이고 a' 는 이미 한 번 실패한 구조(47중 1)다. 이안카 서버를 화면 요청마다 두드리지 않는 방식은 사본뿐이다.
2. 사진을 «일 1회(새벽, ID 지문 바뀐 차만)» 가져오면 이안카 호출량이 작고 24시간 참조 만료와도 맞는다(커맨드 센터 결정 10-14 갱신 주기 일 1회).
3. 읽기·등록 경로(승인 사진 refs, sha256 검증 reader)가 이미 운영 중이라 새 저장소·스키마가 필요 없다.

## 대표 결정이 필요한 것만
1. **드라이브 쓰기 권한**: 현재 수집 쪽은 `drive.readonly`. 업로드용으로 «전용 서비스 계정 1개 + 번호 폴더 상위 폴더 1곳 편집자 공유» 한 가지(범위는 그 폴더만). 권한·공유 설정은 AI 가 바꾸지 않는다.
2. **파일럿 승인**: 노출 이안카 중 10대로 압축 사본→등록→화면 확인 후 전체(93대) 확대.
3. (이미 결정됨, 기록용) 이안카 한정 복사 허용 = 대표 10-14, 갱신 일 1회, refs 스키마 확장 없음.

## 실행 순서(승인 후, 코드 변경은 그때)
1. 서비스 계정·폴더 권한(대표) → 2. 수집 이안카 세션이 압축·업로드(일 1회, 지문 변경분) → 3. `plan-photo-links` 로 CSV → `register-approved-photos --method IANCAR_COMPRESSED_COPY` 로 등록·되읽기 → 4. 파일럿 10대 화면 확인 → 5. 전체. 지문 불일치 보류 사유 `ICAR_PHOTO_FINGERPRINT_STALE` 는 업로드 구현과 함께.
