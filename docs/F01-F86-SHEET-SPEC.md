기계 판독 정본은 `contracts/f01-f86-sheet-spec.v1.json`이다. 이 문서는 그 규격의 설명이다.

## F01 공급사 기준 개편 — 2026-10-03 대표 결정 (설계, 미적용)

기계 정본은 `contracts/f01-f86-sheet-spec.v1.json#f01SupplierLayout`이다. 적용 전까지 아래 「탭명 · 순서 · 색상」이 현재 운영 기준이다.

- F86은 공급사 공동 입력 시트 역할로 바뀌므로 Data가 발행 대상으로 쓰지 않는다. F01은 공급사 기준으로 모은다.
- 공동 입력 시트를 쓰지 않는 공급사 5곳은 회사별 탭 하나씩 둔다: 손오공(RP012, 중고렌트·오공구독·픽업구독을 한 탭에서 상품구분으로 구분), 이안카(RP031), 오토플러스(RP023), 아이카(RP004), 아이언(RP006). 이 5곳은 `supplier-input-sheet-spec.v1.json#supplierChannels.notInSharedSheet`와 같아야 한다(테스트로 고정).
- 공동 입력 시트를 쓰는 공급사(19곳)는 그 시트의 종합을 F01 `공동시트 종합 N대` 탭 하나로 둔다. F01 발행 회차가 읽은 종합 snapshot을 값으로 복사하며, 실시간 참조나 F01→공동 시트 쓰기는 하지 않는다. 같은 차량을 회사 탭과 종합 탭에서 두 번 세지 않는다.
- 전체 묶음 `상품리스트` 탭과 별도 `픽업구독` 탭은 폐지한다. 지우지 않고 숨김·retiredSheetIds로 보존한다. 손오공상품·오플구독 탭의 sheetId는 손오공·오토플러스 탭으로 이어 쓴다.
- 탭명은 `회사명 N대`(공백 구분, 가운데점·시각 없음). 신규 탭 색과 순서(손오공·이안카·오토플러스·아이카·아이언·공동시트 종합)는 제안값이며 적용 전 확인한다.
- 남은 결정: 공동시트 종합(62칸 입력 양식)과 기존 F01 판매 열 구성을 맞출지, 이안카·아이카·아이언 상품이 지금 어느 발행 경로로 들어오는지 확인 후 회사 탭 공급원 고정, primarySheetIds 순서 가정의 새 readback 확인.
- 적용(실행기 `primaryTabs` 4개 고정 해제, 발행기·감사기 연결, 실제 시트 쓰기)은 시트 관리 틀 개편 작업이 맡고 별도 승인 후 진행한다.

- F01/F86 앞 네 탭은 이름 형식·순서·색상을 동일하게 한다.
- 공백만 구분자로 사용한다. 가운데점(·)을 넣지 않는다.
- 대수는 해당 탭 실제 차량번호 행을 기준으로 재계산한다. 중복 키가 있으면 오류로 보고하며 단순 행수를 합격 대수로 쓰지 않는다. 예시 대수를 상수로 고정하지 않는다.
- 상품리스트에만 서울 시각의 월·일·시간을 표시한다. 이는 같은 발행 회차에 명시한 기준 시각이다. 온라인은 고정된 발행 snapshot의 capturedAt, 표시 전용 작업은 명시한 updatedAt을 사용한다. 작업 완료 시각이나 공급사 원천 전체의 최신성을 증명하지 않으며 원천 시각과 snapshot/release는 별도 증거로 관리한다.
- F86 회사 탭은 기존 순서를 유지한다. 동일 차량을 요약 탭과 회사 탭에서 다시 세어 전체 재고에 더하지 않는다.
- 숨김 관리 탭(AI 운영 매뉴얼, AI 인계, 차종사전 등)은 판매 탭명/대수 규격에서 제외하고 보존한다.
- 오공구독 별도 탭은 폐기한다. 중고렌트와 오공구독 상품은 손오공상품 안에서 구분한다. 상품구분 값 오공구독 자체를 없애는 것이 아니다.

## 표 안의 규격

- 고정 열 너비: `차명(원문)` 260px, `옵션(원문)` 360px, `세부트림` 100px. F01/F86에서 해당 헤더가 있는 모든 판매 탭에 동일 적용한다.
- 픽업구독은 설명형 보증금 값을 자르지 않도록 `반납형보증금`과 `인수형보증금`을 각각 180px로 고정한다. 같은 이름이 다른 논리 탭에 있더라도 이 탭별 규격을 임의 확장하지 않는다.
- 긴 원문은 셀 값을 줄이거나 행 높이를 늘리지 않고 기존 CLIP 표시를 유지한다. 링크 원문 열과 금액 열은 화면 전체 폭을 낭비하지 않도록 기존 폭을 보존한다.
- 본문 의미색은 `contracts/f01-f86-sheet-spec.v1.json`의 `appearance.semanticColors` 한 벌만 사용한다. F01·F86을 포함한 모든 Google Sheets 소비자는 상품구분·상태·미입력·링크·기간 배경색을 임의로 재정의하거나 덮어쓰지 않는다.
- F86의 레트로 차이는 맑은 고딕 9pt·기울임·고정 열 순서/폭·12개월 이하 단기 열 숨김에 한정한다. 레트로 적용 단계가 공용 조건부서식을 제거하거나 머리글·본문을 별도 색으로 다시 칠하면 실패다.
- 헤더 1행 고정, 실제 데이터 전체 폭/높이에 필터를 적용한다. 정렬은 행 전체로 이동한다.
- 차명 축·옵션은 왼쪽, 금액·수치는 오른쪽 정렬을 기본으로 한다. 날짜/상태 등은 기존 의미별 규칙을 보존한다.
- 금액은 원래 숫자와 표시 형식을 보존한다. 기간별 대여료·보증금, 반납형·인수형, 주행거리 조건을 합치거나 대표값으로 축약하지 않는다.
- F86의 금액 영역은 24개월 이상 장기대여료와 장기 보증금/규칙을 보여 준다. 12개월 이하 단기 대여료와 `단기보증`만 삭제하지 않고 숨김으로 보존한다. 기간이 붙지 않은 반납형·인수형 보증금은 장기 보증 정보로 표시한다. F01 단기·보증금 열은 유지한다.
- F86 첫 네 탭 문패는 `MM.DD HH:mm 상품리스트 N대`, `손오공상품 N대`, `픽업구독 N대`, `오플구독 N대`다. 뒤의 렌터카사 탭도 `회사명 N대` 형식이며 중간점이나 별도 시각을 넣지 않는다.
- 배차상태·상품구분·미입력·링크의 색은 기존 의미별 색상 정본을 사용한다. 탭 색과 혼용하지 않는다. 불명확한 값은 0으로 채우지 않는다.
- 구분: 손오공상품=RP012/SON_NO_KONG의 중고렌트+오공구독, 픽업구독=TCAR_EXTERNAL, 오플구독=RP023. 원천/금액/상태 변경은 이 표시 규격만으로 정당화하지 않는다.

## 발행기 적용 및 검증

### 손오공 사진 연결 복구 — 2026-09-30 사용자 지시

손오공 일반 상품과 이안카(RP031)의 ERP 직접 차량사진(`image_urls` 등)이 있는데 `photo_link`가 비었다는 이유로 차량번호 링크를 비우지 않는다. 이안카의 인증 사진은 기존 ERP `/api/img?product=...&photo=...` 경유 참조를 사용한다. 직접 사진과 안정 상품 식별자가 있으면 기존 ERP 공개 전체 갤러리로 연결한다. `product-share.guestShareUrl`의 기존 토큰 규칙을 재사용하며 별도 토큰/사진 저장소/수집기/시트 writer를 만들지 않는다. 원문 사진과 전체 이미지 배열은 보존하고 `doc_images`는 공개사진 근거에서 제외한다. 픽업구독 T카 링크, 다른 공급사의 링크 규칙, 폴더만 있는 차량의 원천 링크는 유지한다. 이 링크는 조회용 중립 링크이며 영업 담당자 귀속을 임의 생성하지 않는다.

현재 변경은 기존 publication bridge의 누락·첫 장 연결 장애 복구안이다. 운영 pin 전환과 F01/F86 발행·새 readback 전에는 LIVE 완료로 표현하지 않는다. 대표사진 열 추가안(PR493)은 CLOSED/미병합 상태이며 이 복구가 그 열의 운영 반영을 의미하지 않는다.

- 날짜가 상품리스트 이름 앞에 오므로 startsWith('상품리스트') 방식은 사용하지 않는다. 논리 탭 키 또는 확인된 sheetId로 식별한다.
- F01/F86을 같은 규격으로 일괄 처리하고 기존 sheetId를 보존한다. 오공구독 별도 탭을 다시 만들지 않는다.
- 재고 갱신은 검증한 원천과 동일 스냅샷을 사용하고, 통합 전 원본을 보존한다.
- 탭명·순서·색·고유 차량번호 대수·셀 값·필터 범위를 재조회한다. 시트 표기 성공을 원천 정합성 PASS로 바꾸지 않는다.
- 모든 발행 회차는 위 pixelSize를 다시 적용하고 새 readback에서 정확히 일치해야 성공이다. 사용자가 맞춘 규격이 다음 데이터 발행에서 기본 폭으로 되돌아가면 실패로 처리한다.

## 현재 적용 범위

2026-09-22 현재 이 규격은 운영 Actions의 고정 엔진 `46484b8cccfd3a1b55cf49aad4f6e67ebe983807`과 main workflow에 연결돼 있다. 회차 ID를 비운 `apply=true / ALL` 재적용 run `35681159372`에서 최신 유효 READY snapshot을 자동 선택했고, F01 386·손오공상품 57·픽업구독 216·오플구독 55대, F86 714대, 원자↔F01↔F86 칸 대조와 사진 링크 감사까지 PASS했다. 숨긴 과거 F01 탭은 보존하되 발행·대수·감사에서 제외한다.

규격·발행기·감사기·운영 pin·수동 재적용 경로는 main에 영속 반영됐다. GitHub workflow는 `17 * * * *`로 active이고, 매시 42분의 read-only watchdog은 최근 90분 안에 `schedule`·`repository_dispatch`·heartbeat `push`·`workflow_run` 성공/진행 회차가 없을 때만 같은 canonical writer를 다시 호출한다. watchdog은 Firestore나 시트에 직접 쓰지 않는다.

2026-09-22 강제 복구 검증에서 watchdog run `35687124823`이 canonical `repository_dispatch` run `35687135474`를 생성했다. 이 회차는 새 원천 수집→freepasserp5 원자 갱신→스냅샷→F01/F86 발행→감사까지 PASS했다. 스냅샷은 현재 재고 714대였고 F01/F86 누락·잔존·값 차이 0, F86 65,124칸 어긋남 0이었다. 복구 실행 경로는 실증됐지만 cron 전환 뒤 native `schedule` 이벤트 자체의 실제 생성·성공 증거는 아직 없다. 첫 native 자동 회차가 관측되기 전까지 그 전달 증거만 `HOLD_NATIVE_SCHEDULE_OBSERVATION`으로 둔다. 수동 강제 복구 PASS를 native 예약 전달 PASS로 확대하지 않는다.
